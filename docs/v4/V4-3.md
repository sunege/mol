# V4-3 軌道が wasm 境界と Worker の契約を越える

**依存: V4-1, V4-2**

**目的**: 「軌道の一覧」と「1 本の軌道の等値面」を Worker の契約に通す。UI はまだ触らない。

## 前提

- **契約は `web/src/worker/protocol.ts` が唯一の情報源。** 失敗は `error` で返し、例外を越境
  させない。終端かは `isTerminal()`。
- **SCF は高い、面は安い。** `Calculation` は Worker 側で生き続け、しきい値を動かすと
  marching cubes だけをやり直す（数 ms）。**キャンセルは `terminate()` + 再生成**なので、
  保持中の `Calculation` も消える（UI は `hasDensityRef` で追う）。
- **段（`ModelLevel`）は識別子だけが境界を越える。** 基底名は越えない。
- **WASM の線形メモリは縮まない**（ベンゼンを「測る」と Worker 1 本で 420〜625 MiB）。
  格子 1 枚は 2.4 MB。
- V4-2 で `dft-core` に入ったもの: `orbital::list`（**スピンの組ごと**。閉殻は 1 組、開殻は
  α・β の 2 組）/ `degenerate_groups` / `signed_column` / `overlap_population` /
  `probe_amplitudes` / `spin_pairing`、`density::evaluate_orbital`、`count_lobes`。
- **開殻は畳まない**（plan-v4.md の決定 9）。O₂ は α の π\* が埋まり β は空、同じ π\* が
  α −0.081 / β −0.001 Ha と交換分裂が大きいので、1 本の準位にまとめると消える。
  **α と β の対応は添字ではなく `spin_pairing`**（O₂ で 4→5、5→6、6→4）。
- 実測: 軌道 1 本の評価はベンゼンで 0.256 秒（ネイティブ）。ブラウザの等値面は v3 の実測で
  ベンゼン 1.1 秒。
- **V4-1 で入ったもの**（`Calculation` と `DensityRequest` の作りが変わっているので、下の
  「やること」はこれに合わせて読む）:
  - `Calculation` の格子のキャッシュは **`grids: Vec<(DensityChannel, DensityGrid)>` 1 本**
    （`total` / `bonding` の 2 フィールドはもう無い）。鍵は**要求ではなく `DensityChannel`**
    なので、π の無い分子では `"bonding"` と `"deformation"` が同じ 1 枚を共有する。
  - **軌道の格子は `grids` に入れない。** `DensityChannel`（`dft-core`）に軌道は無いし、方針も
    違う（3 枚とも残す密度に対し、軌道は最後の 1 本だけ）。`grids` の隣に別のフィールドで持つ。
  - **そのキャッシュの鍵は添字だけでは足りない。** 開殻では α の i 番目と β の i 番目が別物
    なので `Option<(usize, SpinChannel, DensityGrid)>`（スピン込み）にすること。
    添字だけだと O₂ で上向きと下向きを切り替えても同じ面が返る。
  - `isosurface` は先に `channel` を `DensityChannel` に直してから `grids` を引く作りなので、
    `"orbital"` はその手前で分岐する。
  - `DensityRequest` は `'total' | 'bonding' | 'deformation'` の 3 つ。**`'orbital'` を足すと
    `Record<DensityRequest, …>` が 2 か所で欠けてコンパイルが落ちる**:
    `ISO_RANGES`（`web/src/components/IsoLevelSlider.tsx`）と App の `levels`。UI を触らない
    チケットだが、この 2 つは埋めておく（値は V4-4 が決める 0.005〜0.15 / 初期 0.03 でよい）。
  - `ScfOutcome` に `hasPi: boolean` が増えている（π の等値面を出せる分子かどうか。F4 の
    対象外＝平面かどうかは画面を見れば分かる幾何）。`OrbitalLevel.parity` とは別物で、
    こちらは分子に 1 つ。

## やること

1. **protocol.ts**:
   - `export type SpinChannel = 'both' | 'up' | 'down'`（閉殻は `'both'` 1 つだけ）。
   - `export interface OrbitalLevel { spin: SpinChannel; first: number; count: number;
     occupation: number; energy: number; parity: 1 | -1 | null; partner: number | null }`。
     `count` は縮退の本数、`first` は**そのスピンの組の中での**添字、`occupation` は
     1 本あたり（`'both'` なら 2 か 0、開殻なら 1 か 0）、`partner` は**もう一方のスピンの
     対応する段**（`levels` 配列への添字。`spin_pairing` から作る。無ければ `null`）。
     **`energy` は準位の高さを決めるためだけに渡す。数値として画面に出さない**
     （`ScfOutcome.multiplicity` と同じ扱いだと doc コメントに書く。理由: LDA の軌道エネルギーの
     絶対値は桁が違う。水の HOMO は −1.6 eV、実験のイオン化エネルギーは 12.6 eV）。
   - 要求 `{ id; type: 'orbitals' }` と応答 `{ id; type: 'orbitals'; levels: OrbitalLevel[] }`。
     **開殻は α の段を全部、続けて β の段を全部**（`spin` で見分ける）。
   - `DensityRequest` に `'orbital'`、`isosurface` の要求に `orbital?: number` と
     `spin?: SpinChannel`、答えの `DensityChannel` に `'orbital'`。
   - `IsoMesh` に `lobes: { positive: number; negative: number }`（他のチャネルでも埋める）。
   - `isTerminal()` は `'orbitals'` を終端として扱う（`type !== 'step' && type !== 'progress'`
     のままで通るが、テストに 1 行足す）。
2. **`dft-wasm`**:
   - `Calculation::orbitals()` — `orbital::list` の組ごとに `degenerate_groups` で段にまとめ、
     `spin_pairing` から `partner` を埋める。エネルギーは Hartree のまま渡す。
     **`spin_pairing` は軌道どうしの対応**なので、段（縮退の組）に畳むときは
     「組の代表どうしが対応していれば段どうしが対応」でよい。
   - `Calculation::isosurface` に `"orbital"` を足し、`index` と `spin` を受ける。
     **軌道の格子はいちばん最後の 1 本だけキャッシュする**（`orbital: Option<(usize,
     SpinChannel, DensityGrid)>`。**スピン込みの鍵**。上の「V4-1 で入ったもの」を見ること）。
     同じ軌道でしきい値だけ変えたら作り直さない。軌道を変えたら捨てて作る。
     理由はメモリ（線形メモリは縮まない）。
   - `signed_column` を通した係数で評価する（位相の色が毎回同じになる）。
   - `count_lobes` の結果を `IsoMesh` に載せる。
   - **段で断らない**: 軌道を「形を探す」の結果だけに限るのは画面の決まりで、UI が守る（V4-4）。
3. **`dft.worker.ts`**: `orbitals` の case、`isosurface` に `request.orbital` を渡す。
   メッシュの転送は今と同じ形（`lobes` はただの数）。
4. **`workerClient.ts`**: `orbitals(): Promise<OrbitalLevel[]>` と
   `isosurface(channel, isoLevel, orbital?, spin?)`（**足すのは末尾**、段のときと同じ作法）。
5. **`engine.test.ts`**（実物の `.wasm` を呼ぶ）: 水を解いて
   - `orbitals()` が 7 段、占有 2 が 5 段、空が 2 段、全部 `spin: 'both'`。
   - 軌道の等値面が正と負の両方の面を返すこと。
   ベンゼンで HOMO の段の `count` が 2 であること。
   **O₂** で `spin` が `'up'` と `'down'` の 2 組に分かれ、**上向きの占有が 9 本、
   下向きが 7 本**で、`partner` が埋まっていること。
