# V4-4 「分子軌道」の節と軌道の等値面（位相）

**依存: V4-3**

**目的**: パネルに「分子軌道」の節を足し、軌道を 1 本ずつ、位相の色つきで見られるようにする。

## 前提

- **モードは作らない。** パネルに `<details>` の節を 1 つ足し、**既定は閉じておく**。
  開かない人の画面は v3 のまま（plan-v4.md の決定 1）。
- **F4 は「既定の画面に出さない」に読み替える。** この節の中でも**基底・汎関数・電荷・多重度・
  試行回数は出さない**。**軌道エネルギーの数値も出さない**（LDA の絶対値は桁が違う）。
- **軌道の節の中身を出すのは `resultLevel === 'shape'` のときだけ**（決定 4）。
  「形を測る」の結果のときは 1 行だけ出す: 「軌道は『形を探す』で計算したときに見られます」。
  理由: 最小基底は 1 原子 1 軌道 ＝ 教科書の絵そのもの、本数もベンゼンで 36 対 102。
- **縮退は組として扱う**（決定 5）。1 行が `OrbitalLevel` 1 つ ＝ 同じ高さの軌道の組で、
  `count` が 2 以上なら行の中で「1 / 2」を切り替える。**1 本だけ見せるのは誤り**
  （ベンゼンの HOMO は 2 本で、片方は C1 と C4 に振幅が無い）。
- **開殻は上向きと下向きを分ける**（決定 9）。`OrbitalLevel.spin` が `'both'`（閉殻）/
  `'up'` / `'down'`、`partner` がもう一方の対応する段。**畳まない**（O₂ の同じ π\* が
  α −0.081 / β −0.001 Ha と離れている）。**多重度が画面から読めるのはここだけ許す**
  （決定 2。O₂ の「π\* に同じ向きのスピンが 1 個ずつ」は教える中身そのもの）。
  実測: O₂ は上向き 9 本・下向き 7 本が占有で、**上向きの上から 2 本（縮退）が π\***。
- App が持っているもの: `channel` / `levels`（チャネルごとのしきい値）/ `showDensity` /
  `solved` / `resultLevel` / `hasDensityRef` / `requestIsosurface`（`wantedRef` で合流）。
  しきい値の範囲は `components/IsoLevelSlider.tsx` の `ISO_RANGES`。
- **文言は `web/src/components/` のテスト付きモジュールに分ける慣習**
  （`components/level.ts` と `components/search.ts` がその形）。
- 密度の最大はベンゼンで 22（核の上）だが、**軌道の振幅は ±0.22**。しきい値の範囲は別物。
- **V4-1 で入ったもの**（「電子密度」の節が変わっている）:
  - 密度のボタンは 3 つになり（すべての電子 / 結合に寄与する電子 / 原子から動いた電子）、
    文言と**どれを出すか**は **`web/src/components/density.ts`**（`channelLabel` /
    `explainChannel` / `offeredChannels(hasPi)`）。`explainChannel` は App.tsx から移した。
    文言モジュールの書き方はこれがいちばん新しい例。
  - **落とし穴**: App に `const offered = offeredChannels(hasPi)` と、**「選択中のボタンが
    `offered` に無ければ `'total'` に戻す」effect** がある。`offeredChannels` は密度の 3 つしか
    返さないので、**このままだと `channel = 'orbital'` にした瞬間に `'total'` へ戻される。**
    effect を密度の要求のときだけ見るように狭めること（`channel !== 'orbital'` を足すのが
    いちばん小さい）。
  - やること 5「同時に 2 つ描かない」の半分は既にできている: ボタンの `active` は
    `channel === request` なので、`channel = 'orbital'` のあいだ密度のボタンはどれも
    選択状態にならない。
  - **App の `hasPi` は `hasDensityRef` と寿命が違う**（同じ分子を計算し直すあいだ π のボタンと
    選択が消えないよう、わざと消していない）。やること 6 の「`hasDensityRef` が落ちたら捨てる」を
    `hasPi` に広げないこと。
  - `ISO_RANGES` には `deformation`（`bonding` と同じ 0.002〜0.15 / 初期 0.02）がある。
    `orbital` はその隣に足す。
- **V4-3 で入ったもの**（契約は `protocol.ts` が唯一の情報源。実物の値は
  dev-notes「V4-3 の実装メモ」）:
  - `client.orbitals()` → `OrbitalLevel[]`。**`first` はそのスピンの組の中での軌道の添字で、
    `levels` 配列の添字ではない**（開殻では上向きと下向きで同じ `first` が並ぶ）。
    **`partner` だけが `levels` 配列の添字**。
  - **「9 本」は軌道の本数で、段の数ではない。** O₂ は **16 段**（上向き 8・下向き 8）で、
    占有は上向き **7 段 ＝ 9 本**、下向き **6 段 ＝ 7 本**（`count × occupation` の和）。
    完了条件の「9 段分・7 段分」はこの意味で読む。上向きの π\* は段 6（`first: 7`、
    `count: 2`、`occupation: 1`）で、その `partner` が下向きの段 14（`first: 7`、`count: 2`、
    `occupation: 0`）＝ 教科書の O₂。
  - **軌道の等値面は `isosurface(channel, isoLevel, orbital?, spin?)`**（足したのは末尾）。
    `channel: 'orbital'` のとき `orbital` は必須で、**`spin` を省くと `'both'`**＝
    **開殻ではエラー**になる（推測しない）。`wantedRef` の合流にはこの 2 つも載せること。
  - **`ISO_RANGES.orbital` は入れてある**（0.005〜0.15 / 初期 0.03。やること 4 の前半は済み）。
    `App` の `levels` にも `orbital` がある。
  - **`density.ts` の `LABELS` と `WORDS` にも `orbital` を入れてある**（`Record` の網羅性で
    コンパイルが落ちるため）。**文言は仮で、このチケットのもの。** `REQUEST_ORDER` には
    入れていないので**ボタンは 3 つのまま**＝ やること 5 の半分はそのまま効く。
    `density.test.ts` の F4 の禁止語（'軌道' を含む）は**密度の 3 要求しか回していない**ので、
    節が「分子軌道」と名乗ってよい（決定 2）のと矛盾しない。**`REQUESTS` に `'orbital'` を
    足すと落ちる。**
  - **`orbitals()` は等値面と同じで、計算を持っていない Worker では `error` で返る**
    （`cancelAll` で Worker を捨てたあと、まだ 1 回も解いていないとき）。**`hasDensityRef` で
    門番すること**（`requestIsosurface` と同じ扱い）。値段は 0.2 ms なので、取り直しを
    惜しむ必要は無い。
  - `IsoMesh` に **`lobes: { positive, negative }`**（いまのしきい値でのローブの数）が増えた。
    使うのは V4-5 だが、軌道の面が「出ている」ことの確認には面数より読みやすい。
  - ベンゼンの HOMO の振幅は実測で **±0.257**（前提の「±0.22」より少し大きい）。
    既定の 0.03 で HOMO は正負 2 個ずつのローブになる。

## やること

1. **`web/src/components/orbital.ts`（新規）**: 一覧の行の言葉。
   - 占有の記号（`●●` / `●` / `○`）と、`HOMO` / `LUMO` のラベル
     （**「上から n 番目」のような通し番号は出さない**）。
     **開殻では HOMO / LUMO をスピンごとに付ける**（上向きの最後の占有と、下向きの最初の空）。
   - 縮退の組の言い方（「同じ高さの軌道が 2 つ」）。
   - スピンの列の見出し（「上向きのスピン」「下向きのスピン」）。閉殻では列が 1 つで見出しを出さない。
   - 節が閉じているときの 1 行、「形を測る」のときの 1 行。
   - テストは `orbital.test.ts`。`components/records.test.ts` の `FORBIDDEN` と同じ語を掛ける。
2. **App に節を足す**: `<h2>分子軌道</h2>` を `<details>`（既定は閉じる）。
   開いたときに `client.orbitals()` を 1 回だけ呼ぶ（結果は `atoms` が変わったら捨てる）。
   **`spin` が 2 種類あれば一覧を 2 列にする**（閉殻は 1 列のまま）。
3. **一覧から選ぶと軌道が出る**: `channel = 'orbital'` と選んだ `index` と `spin`。
   `requestIsosurface` の合流（`wantedRef`）に軌道の番号とスピンも載せる。
4. **`ISO_RANGES.orbital`**: 0.005〜0.15、初期値 0.03 から始める（**V4-9 で実測して詰める**）。
   スライダーの左右の言葉（今は「広がり」「密な芯」）も軌道用に。
5. **同時に 2 つ描かない**: 軌道を選んでいる間は密度のボタンの選択を外し、密度に戻ったら
   軌道の選択を外す。
6. **計算が終わるたびに軌道の一覧を捨てる**（`hasDensityRef` が落ちたら選択も捨てる）。

## 完了条件

- `npm test` と `npm run lint --workspace web`。
- `orbital.test.ts` で **F4 の禁止語が出てこないこと**と、HOMO / LUMO のラベルが占有から
  決まること。
- Claude のブラウザ（WebGL 無し）で**パネルの動作**: 水を計算して節を開くと 7 段出ること、
  HOMO を選ぶと正と負の両方の面が返ること（面数で見る）、しきい値を動かしても
  **一覧が再計算されない**こと、「形を測る」で計算すると 1 行だけになること。
  **O₂ で列が 2 つになり、上向きの占有が 9 段分・下向きが 7 段分**であること。
- **3D の見た目（位相の青と赤）はユーザーに Firefox で確認してもらう**（V4-10）。
