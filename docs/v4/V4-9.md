# V4-9 速さとメモリの実測、しきい値と予算の見直し

**依存: V4-4〜V4-8**

**目的**: v4 で足したものが、開発機とブラウザで実際にいくらかかるかを測り、
仮で置いた数字（しきい値の範囲、キャッシュの本数、点の数の上限）を実測で決め直す。

## 前提

- **時間の比較は Node で取る**（`--target nodejs` の release を小さなスクリプトから呼ぶ）。
  Browser ペインは非表示だと間引かれ、この機械（2 物理コア）は同じバイナリでも **±30% ぶれる**
  ので**複数回の最小値**で判断する。手順は dev-notes「コマンドの詳細」。
- **WASM の高速化は WASM のプロファイルで決める**（内訳はネイティブとまるで違う）。
- 比較の相手（v3 の実測、この開発機、Node、3 回の最小値）:

  | | 形を探す | 形を測る |
  | --- | --- | --- |
  | 水の一点計算 | 0.8 秒 | 1.9 秒 |
  | ベンゼンの一点計算 | 3.3 秒 | 71 秒 |
  | 最初の等値面（全電子 / 結合） | 1.1 / 0.8 秒 | 2.6 / 2.2 秒 |
  | Worker の線形メモリ（一点） | 47 MiB | 243 MiB |

- ネイティブの実測（dev-notes「v4-0 の実測」）: 軌道 1 本の評価はベンゼン 0.256 秒
  （全電子密度 0.334 秒）、H₂ の 27 点スキャンが 0.41 秒。
- 仮で置いてある数字:
  - `ISO_RANGES.orbital` ＝ 0.005〜0.15、初期値 0.03（V4-4）
  - 軌道の格子のキャッシュは**最後の 1 本だけ**（V4-3）
  - スキャンの点の数の上限 60（V4-7）
  - 節を数えるときの探針点は核から 1.0 Bohr（V4-2）

## やること

1. **測る**（水・エチレン・ベンゼン・**O₂**、「形を探す」）:
   - `orbitals()`（格子を作らないので速いはず。**開殻は `spin_pairing` の行列積が 1 回増える**）
   - 軌道 1 本の最初の等値面、同じ軌道でしきい値だけ動かしたとき、軌道を切り替えたとき
   - `orbitalCharacter()`
   - H₂・N₂・**O₂** のスキャン（27 点と 60 点。**開殻は準位が 2 倍**。ネイティブでは
     O₂ の 1 点が 0.08 秒、NO は 39 反復で 0.81 秒と幅がある）
   - **Worker の線形メモリの山**（軌道を何本も切り替えたあと。**線形メモリは縮まない**）
2. **決め直す**:
   - **しきい値の範囲と初期値**: 分子ごとに「何も見えない」が起きない範囲にする
     （軌道の振幅はベンゼンの HOMO で ±0.22。密度の最大 22 とは別物）。
   - **キャッシュの本数**: 1 本のままか、前後数本を 1 パスでまとめて作るか
     （同じ 1 パスで φ を使い回せば複数本がほぼ 1 本の値段。格子 1 枚 2.4 MB）。
     **決め手は前面の応答**（v2 の探索プールと同じ判断の仕方）。
   - **スキャンの点の数の上限**と、既定の点数。
3. **文言の時間の目安**を実測に合わせる（V4-8 のスキャンに「数秒」と書いているなら確かめる）。
