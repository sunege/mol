# V3-2 6-31G\* の参照値とテスト

**依存: V3-1（`BasisSet::build` と `System` の `kind` がある前提）**

**目的**: 6-31G\* の経路を、STO-3G と同じ厳しさで参照値に固定する。

## 前提

- **規約: 参照値を記憶から書かない。** すべて `scripts/gen_reference.py`（PySCF）の生成物か、
  テストの中で独立な経路から導く。
- `gen_reference.py` には既に **`integral_reference(key, name, basis, cart, full_eri)`** があり
  （`integrals_h2o_631gs.json` はこれで作られている）、**`scf_reference(key, name, with_density)`**
  と **`relaxed_geometry(name, multiplicity)`** は STO-3G 決め打ち。
- **Cartesian d を使う**（`cart=True`）。エンジンは Cartesian で、6D と 5D では関数の数が違う
  （ベンゼンで 102 対 96）。
- 6-31G\* で PySCF と一致することは v3-0 で確認済み: 水 −75.844389 対 −75.844388、
  ベンゼン −230.090762 対 −230.090758（どちらもプリセット構造、`lda,vwn5`）。V3-1 の後、
  `System::build` 経由（SAD の初期推定）でも同じ値が出る。

### V3-1 で入ったもの（2026-09-21）

- 引数の順は **分子 → 基底 → グリッド**: `System::build(molecule, kind, quality)` /
  `System::build_with_grid(molecule, kind, grid)`。既存のテストはすべて `BasisKind::Sto3g` を
  明示して呼んでいる（`tests/*.rs` は `use dft_core::basis::BasisKind;` 済み）。
- **6-31G\* で既にあるテスト**: 表（`reference_integrals.rs` の `b631gs_table_matches_reference`）、
  積分（同 `d_functions_are_handled`）、緩和が基底を保つこと（`optimize.rs` の
  `every_step_keeps_the_basis_it_started_in`。**参照値は見ていない**）、`scf/guess.rs` と
  `basis/mod.rs` の単体テスト（両方の基底）。**エネルギー・緩和構造・勾配を 6-31G\* の参照値に
  固定したテストはまだ無い**。それがこのチケット。
- `scf_*.json` には既に `"basis": "sto-3g"` が書かれているが、Rust の `ScfReference`
  （`tests/common/mod.rs`）はそれを読んでいない（serde は知らないキーを黙って無視する）。
  `basis` を読み、`BasisKind` に写すのが素直。
- `build_mol()` の既定は `cart=False`。**6-31G\* の参照では `cart=True` を渡し忘れないこと**
  （忘れると PySCF は球面の 5D になり、関数の数が合わない）。`relaxed_geometry()` の中の
  `build()` も `mol.basis = "sto-3g"` 決め打ちで、`cart` を設定していない。
- **既存の STO-3G の値が 1 つも動いていないことの確かめ方**: dev-notes「V3-1 の実装メモ」。
  f64 のビット列のハッシュを変更の前後で diff する。生成器に手を入れたら、STO-3G の生成物が
  バイト単位で同じことも `git diff` で見る。

## やること

1. `scf_reference()` に基底の引数を足し、**水・メタン・アンモニア**の 6-31G\* 版を出す
   （`scf_h2o_631gs.json` など。名前は既存の付け方に合わせる）。ベンゼンは重いので入れない。
2. `relaxed_geometry()` にも基底の引数を足し、**水の 6-31G\* の緩和構造**を 1 つ出す。
   v3-0 の値は r(OH) = 0.9762 Å / ∠HOH = 103.65°（参考。**テストに書き写さず生成物にする**）。
3. `tests/reference_scf.rs` と `tests/optimize.rs` が両方の基底で回るようにする。
4. 勾配: `integrals/deriv.rs` には既に **d シェルの項ごとの有限差分テスト**（`with_d_functions`）
   がある。6-31G\* の実基底で 1 本足せるなら足す（`tests/gradients.rs`）。
5. `npm run build:wasm` はこのチケットでは不要。ただし条件がある: 触るのが `tests/`・`scripts/`・
   `src/` の中の `#[cfg(test)]` のモジュール（ファイル末尾）だけならよい。`src/` の非テストの
   コードに触れたら、コメントだけの変更でも要る（CLAUDE.md「ビルド・CI・デプロイ」）。

## 完了条件

- `cargo test --workspace` が通り、**6-31G\* の SCF・緩和・勾配が参照値に固定されている**。
- `scripts/gen_reference.py` を丸ごと回し直して、次の 2 つが成り立つ（1 回 4 分半）。
  - **決定的な生成物はバイト単位で同じ**: 表 2 つ・Lebedev・`xc_lda`・`integrals_*`・
    `scf_h2`・`scf_open_shell`・`units.json`、それとこのチケットで足した値のうち決定的なもの。
  - **SCF の JSON の差は収束ノイズの大きさ（1e-10 Ha 未満）だけ**。
- 補足: V3-1 の時点で、既存の STO-3G の `scf_*.json` と `gradients.json` は回すたびに最大 5e-11 揺れる
  （BLAS の足し算の順序。スレッド数や、同じプロセスで先に何を解いたかで変わり、固定できない。
  dev-notes「V3-1 の実装メモ」）。**このチケットで意図して変えたファイル以外の揺れはコミットせず、
  `git checkout` で戻す**。
