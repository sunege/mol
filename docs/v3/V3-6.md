# V3-6 探索は「形を探す」に固定する

**依存: V3-3**

**目的**: 並列探索（パネルの「形をさがす」）を最小基底に固定し、その理由を文言でも示す。

## 前提（数字が理由そのもの）

- プールの大きさは `poolSize = min(MAX_CONCURRENT(=3), max(1, floor(hardwareConcurrency/2) − 1))`
  （`web/src/search/pool.ts`）。講義 PC（12 スレッド）では 3 になる。
- **Worker 1 本がベンゼン STO-3G で 139 MiB**（P10-1 の実測）。
- **6-31G\* では ERI テンソルだけでベンゼン 105 MiB** になり、Worker 1 本は **250 MiB 前後**。
  **WASM の線形メモリは縮まない**ので、3 本回すと 1 GiB に近づく。
- 探索は「どんな形に落ち着くか」を見る機能で、**その用途は「形を探す」の段そのもの**。
  v3-0 の実測でも、形（極小の選び方）は段を上げても変わらない。

### V3-3 で入ったもの（2026-09-21）

- `client.optimize(z, xyz, onStep, onProgress?, budgetMs?, level?)`（段は**末尾**、型は
  `protocol.ts` の `ModelLevel`）。`pool.ts` の呼び出しは今 `(…, undefined, this.#budgetMs)` で
  終わっているので、その後ろに `'shape'`。省略でも `'shape'` で解かれるが、**固定は明示して
  書く**（コメントとテストの対象にするため）。`pool.test.ts` の `optimizeRequest()` が返す
  リクエストの `level` で確かめられる。

### V3-4 で入ったもの（2026-09-22）

- 前面の選択は `App.tsx` の `level` state（「計算」の見出しの下のスイッチ）。探索のプールは
  これを読まない（今も `optimize` の段を省略している）。段の名前を文言に出すなら
  `components/level.ts` の `levelLabel('shape')`。
- **名前の重なり（ユーザーに判断を仰ぐこと）**: パネルでは新しい段のボタン**「形を探す」**の
  すぐ下に、この探索の見出し**「形をさがす」**がある。読みが同じで、講義では同じものに聞こえる。
  段の名前は確定なので、変えるとすれば探索の見出し（`SearchPanel.tsx` の `<h2>`）のほう。
  V3-4 では触っていない。

### V3-5 で入ったもの（2026-09-22）

- **探索の候補から作る記録は `'shape'`**: `App.tsx` の `SearchPool` の `onFinished` →
  `createRecord({ …, level: 'shape', source: 'search' })`。コメントは「プールは段を省略して
  投げ、Worker は省略を `'shape'` と読む」。**プールが `'shape'` を明示して投げるようにしたら、
  このコメントを直し、2 つがずれないようにする**（例: `pool.ts` に定数を置いて App の記録も
  それを使う）。記録の段は `record.model`（`engineModel(level)`）に入るだけで、段の
  フィールドは無い。
- 探索の行が出す「いちばん低い形からの差」は `entryFor(recordGroups, candidateId)` の群の中の
  数字で、**段が違う記録は別の群**なので、前面の「形を測る」の記録と順位がつくことはない。
- **名前の重なりが 1 つ増えた**: 記録の群の見出しにも段が出る（`H₂O · 形を探す · 3 件`、
  `components/records.ts` の `groupHeading()`）。ユーザーに判断を仰ぐときに合わせて伝える。
- F4 の禁止語: `components/records.test.ts` に `FORBIDDEN`（`6-31G` と `VWN` 入り）があるが、
  そのファイルの中だけの定数。`search.test.ts` の今のリスト（68 行目付近）には `6-31G`・
  `LDA`・`汎関数` が無い。

## やること

1. `web/src/search/` が**段を取らない**ことをコードとコメントで明示する
   （`pool.ts` が `optimize` を呼ぶところで `'shape'` を固定で渡し、理由を 1 行）。
2. `web/src/components/search.ts` の説明文に、**探索は形の段で回ること**を 1 行足す
   （**F4 に触れない言葉で**。「速い段で、形だけを見ます」程度）。
3. 前面で「形を測る」を選んでいても、探索は形の段のまま回ることをテストで固定する。

## 完了条件

- `npm test` が通り、**プールが常に形の段で投げる**ことがテストで固定されている。
- `search.ts` のテストで、足した文言に禁止語が無いこと。
