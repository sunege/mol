# V3-7 中断してもそこまでの形と数値を残す

**依存: V3-3（段が通っていること。ただし中身は段と独立なので先にやってもよい）**

**目的**: 「中止」を押したときに開始前へ戻さず、**そこまで進んだ形**と、できれば**数値**を残す。
「形を測る」でベンゼンが 2 分かかるので、中断は普通の操作になる。

## 前提

- 今の中断は `App.tsx` の `cancelCalculation()` → `clientRef.current?.cancelAll()` で
  **`terminate()` + Worker 再生成**。単スレッドの WASM 計算は外から止められないため。
  Worker と一緒に**保持中の `Calculation`（密度）も消える**ので、等値面は SCF からやり直し
  （`hasDensityRef`）。
- **`optimize` は受け入れた構造を 1 歩ごとに `step` で流しており**（`protocol.ts` の
  `OptimizationStep` は `xyz` と `energy` を持つ）、**App は `stepsRef` に集めている**。
  → **形だけなら、今すぐ残せる。**
- **数値まで残す道は既にある。** 候補プールの `budgetMs` は、Worker の JS が `on_step` から
  **例外を投げる**ことで止めている（`dft.worker.ts` の `throw new Error('candidate budget')`）。
  そのとき engine は `reason: 'interrupted'` と**そこまでの構造**を返し、**最後の `scf` も来る**。
  **Rust は一行も要らない。** 足りないのは「忙しい Worker に止まれと伝える手段」だけ。
- 規約: **「解けなかった」と「間に合わなかった」は別物。** 時間切れ・回数上限は構造を残して
  数値と理由を出す（判定は `hasUsableStructure()`）。**中断も後者として扱う。**

### V3-4 で入ったもの（2026-09-22）

- **`cancelCalculation()` は「中止」ボタン専用ではない**: 編集のたびの `invalidateResult()`、
  プリセットのボタン、`openRecord()` からも呼ばれる。しかも `placeAtom` やプリセットは
  **`setAtoms` を先に呼んでから** `invalidateResult()` を呼ぶので、(a) の 1 を
  `cancelCalculation()` の中に書くと、計算中の原子の追加やプリセットの切り替えが最後の step で
  **上書きされる**。形を残すのは「中止」ボタンの経路だけにする（ボタンは
  `computing ? cancelCalculation : relax`）。
- (b) で数値が返るときは、**`relax()` の `.then` をそのまま通す**。そこで `resultLevel`（状態の
  行の「（形を測る）」）が入り、V3-5 が入るまでの「`'measure'` の緩和は記録しない」ガードも効く。
  中断した `'measure'` の緩和を別の道で記録すると、STO-3G の `model` で書かれて混ざる。
- 段のスイッチは `computing` の間だけ固まるので、中止すれば選び直せる。

## やること（2 段構え。(a) だけでも価値がある）

### (a) 形を残す（小さい・安全）

1. `cancelCalculation()` で、緩和中なら **`stepsRef` の最後の構造を `setAtoms` する**
   （背景タブでは rAF が走らないので、アニメーションに任せず即 `setAtoms`）。
2. **観測モードのまま留まる**（`restoreMode()` ではなく `keepObserving()`）。
3. 画面には「途中で止めました」と、そこまでの歩数を出す。数値は出せないので `—`。

### (b) 数値も残す（`SharedArrayBuffer` で止める）

4. `vercel.json` に **COOP/COEP** の header を足し、vite の dev サーバにも同じものを足す
   （`web/vite.config.ts` の `server.headers`）。**このアプリは cross-origin の資源を
   読んでいない**ので副作用は小さい。
5. `optimize` のリクエストに**停止フラグ**（`SharedArrayBuffer` の `Int32Array`）を載せる
   （`protocol.ts`）。Worker は `on_step` で `Atomics.load` を見て、立っていたら投げる
   ＝ `budgetMs` と同じ道。**`reason` は `'interrupted'`**（新しい理由は増やさない。
   ユーザーから見て「間に合わなかった」と同じ扱いだから）。
6. `engineSupport.ts` に **`crossOriginIsolated` / `SharedArrayBuffer` の判定**を足し、
   **使えない環境では今までどおり `terminate()`**（=(a) の挙動）に落ちる。
   **使えないことを理由にアプリを止めない。**
7. 数値が返るなら、**記録に「途中」として 1 件**入る（時間切れと同じ扱いで、順位にも谷にも
   入れない）。Worker が生き残るので**等値面もそのまま出せる**（`hasDensityRef` を倒さない）。
