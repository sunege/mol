# V3-3 段を wasm 境界と Worker の契約に通す

**依存: V3-1**

**目的**: 「形を探す」「形を測る」を、UI から Worker、Worker から エンジンまで 1 本の値で運ぶ。

## 前提

- 段は 2 つ。コード上の名前は **`ModelLevel = 'shape' | 'measure'`**。
  `'shape'` = STO-3G（既定、今のまま）、`'measure'` = 6-31G\*。
- **`web/src/worker/protocol.ts` が Worker の契約の唯一の情報源。**
- **`crates/dft-wasm` は単位変換とシリアライズだけ。物理を書かない。**
- **F4**: 基底の名前は境界を越えない。越えるのは段の識別子だけで、画面に出す言葉は UI 側。
- 進捗の段階名は `dft-wasm` の `mod stage` と `protocol.ts` の `progressFromEngine()` の
  2 か所にあり、ずれても落ちずにカードが止まるだけなので、`engine.test.ts` が実物の
  `.wasm` で照合している。**段を足しても、この照合を壊さないこと。**

## やること

1. **`crates/dft-wasm/src/lib.rs`**: `scf()` と `optimize()` に段の引数（文字列 `"shape"` /
   `"measure"` を `BasisKind` に写す小さな関数）。**知らない文字列は既定の `shape` ではなく
   エラー**にする（黙って安いほうで解くと、画面の数値が嘘になる）。
2. **`web/src/worker/protocol.ts`**: `ModelLevel` を定義し、`scf` と `optimize` のリクエストに
   足す。省略時は `'shape'`。doc コメントに「段が違う結果は比べられない」ことを書く。
3. **`web/src/worker/dft.worker.ts`**: 受け取って engine に渡すだけ。
4. **`web/src/worker/workerClient.ts`**: `scf()` / `optimize()` の引数に段を足す
   （`budgetMs` の隣）。
5. **`npm run build:wasm`** して `web/src/wasm/` をコミットする（Vercel に Rust が無い）。
   **`mv` や `cp -p` を使わない**（mtime が戻って古い `.wasm` ができる）。
6. **`web/src/worker/engine.test.ts`**: 実物の `.wasm` に対して、
   **同じ分子を 2 つの段で解くと `basisFunctions` が違う**ことを 1 本。
   （水なら 7 と 19。**画面に出す値ではなく `ScfOutcome` の診断値**なので F4 に触れない。）

## 完了条件

- `cargo test --workspace`、`npm test`、`npm run lint --workspace web` が通る。
- `engine.test.ts` が両方の段を実物の `.wasm` で通す。
- App からはまだ使わない（既定の `'shape'` で今までどおり動く）。
