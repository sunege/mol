# V6-8 原子の線と向きをつなぐ（App・節・viewer）

**依存: V6-6**（Worker の `atom` / `along`）、**V6-7**（`OrbitalPick` の `atom` / `along`・
`directionOf`・`atomOrbitalWords`）。下の「V6-6 / V6-7 で入ったもの」を見る。

**目的**: 相関図の原子の線を押すとその原子軌道を、π の線を押すと向きをそろえた軌道を描く。
向きは**押したときの画面**から決め、後で 3D を回しても描き直さない。

## 前提（今のコード）

- 等値面の要求は App の `wantedRef`（`grep -n "const wantedRef" web/src/App.tsx`）:
  `{ channel, level, orbital?, spin? }`。これを 1 本ずつ流すループが
  `client.isosurface(wanted.channel, wanted.level, wanted.orbital, wanted.spin)`
  （`grep -n "client.isosurface("`）。要求を作るのは `selectOrbital`
  （`grep -n "const selectOrbital"`）と、しきい値・計算のやり直しの周り（`grep -n "wantedRef.current ="`
  で全部見る）。
- `hasDensityRef`: Worker が密度（`Calculation`）を持っているか。無ければ SCF からやり直す。
  原子軌道も**画面の分子の `Calculation`** の上で解くので同じ扱い。
- viewer（`web/src/scene/viewer.ts`）はカメラを外に出していない（`#camera` は非公開）。
- 分子軌道の節（`components/OrbitalPanel.tsx`）は、選んだ軌道について `rungOf(levels, picked)`
  → `describeBonds`・`countNodes`・`describeLobes` の 3 行を出す。原子の pick では `rungOf` が
  null になる（V6-7）。
- 距離スキャンのマーカーを動かすと `carryPick` で選び直す（V6-7 で原子の pick はそのまま）。

## やること

1. **`viewer.ts`**: `cameraAxes(): { right: Vec3; up: Vec3; forward: Vec3 }`（`#camera.matrixWorld`
   から。`forward` は `getWorldDirection`）。数行。
2. **App**:
   - `wantedRef` の型に `atom?: number` と `along?: Vec3` を足し、ループで `client.isosurface` に
     渡す。
   - `selectOrbital(pick)` で、`pick.along` があれば **その場で** `directionOf(pick.along,
     atoms[0].pos, atoms[1].pos, viewer.cameraAxes())` を計算し、その向きを App の状態（pick と
     一緒の 1 つの値。例えば `orbitalDirection`）に固める。しきい値を変えるときも同じ向きで
     要求する（回し直さない）。pick を外す・分子が変わるときに捨てる。
   - `pick.atom` があれば `wantedRef` に `atom: pick.atom, orbital: pick.index`（spin は送らない）。
   - `carryPick` の後（マーカー）も向きは固めたものを使う。
3. **`OrbitalPanel.tsx`**: pick に `atom` があれば、性格の 3 行の代わりに `atomOrbitalWords(...)`
   と `describeLobes`。しきい値のスライダーはそのまま。
4. **`CorrelationDiagram.tsx`**: 原子の線の当たり判定も出す（`picks[k]` が null でなければ、
   V6-4 と同じ）。
5. 節の説明に 1 文（`scan.ts` の `CORRELATION_HINT` か `orbital.ts`）:
   「縮退した部屋は、向き（結合の軸・軸に垂直）を選んで描きます。向きは押したときの画面で
   決まります。」

## V6-6 で入ったもの

- `client.isosurface(channel, isoLevel, orbital?, spin?, atom?, along?)`（`workerClient.ts`）。
  `atom?: number`・`along?: [number, number, number]`。要求（`protocol.ts` の `type: 'isosurface'`）
  にも同じ 2 つの欄。どちらも `channel: 'orbital'` のときだけ読まれる。
  - **原子の軌道**: `isosurface('orbital', level, k, undefined, atom, along)`。`k` は
    `atomLevels` がその元素に返した配列の添字（N なら 0 = 1s、1 = 2s、2〜4 = 2p）。`atom` は画面の
    原子の添字（0 か 1）。`spin` は読まれない（渡しても無視）。
  - **分子の軌道**: 今までどおり `orbital` = `level.first + offset`、`spin`。`along` を付けると
    縮退の組の中の**どの offset でも同じ「向きに向いた 1 本」**になる（2p の 3 本・π の 2 本は
    `first` に向きを変えて渡せばよい）。縮退していない軌道では `along` は無視される。
  - `along` は向きだけ（長さ・単位は問わない。境界で正規化）。**正の塊が `along` の側**に来る。
  - 返る `channel` はどちらも `'orbital'`。格子は 1 本なので、原子の軌道を描くと分子の軌道の格子は
    捨てられる（戻るとまた作り直し、N₂ で 60〜130 ms）。しきい値だけの変更は今までどおり安い。
- エラーの文言（`error` の `message` に入る）:
  - `a direction cannot be zero or infinite`（`along` が `[0, 0, 0]` など）
  - `a direction is three numbers, not 2`（長さ 3 でない）
  - `atom 2 is past the 2 this molecule has`（`atom` が範囲外）
  - `orbital 5 is past the 5 this atom has`（原子の `orbital` が範囲外）
  - 分子の側は今までどおり `orbital N is past the M this calculation has` / `this calculation has no up orbitals: …`

## V6-7 で入ったもの

- **`orbital.ts`**: `export type Along = 'axis' | 'across' | 'toward'`、`ALONG_ORDER`（左から
  `axis, across, toward`）、`ALONG_WORDS: Record<Along, string>`（「結合の軸の向き」「軸に垂直・画面の中」
  「軸に垂直・手前」）。
- **`OrbitalPick` の新しい欄**（どちらも任意）: `atom?: number`（画面の原子の添字 0 / 1。あれば `index` は
  その元素の `atomLevels` の添字 ＝ `client.isosurface` の `orbital` にそのまま渡す値、`spin` は `'both'` で
  読まない）と `along?: Along`。**原子の p は 3 本とも `along` あり、s は無し。分子の π は `across`・
  `toward`、ほかの段は無し。**
  - `samePick` は `index`・`spin`・`atom`・`along` の 4 つを比べる。`rungOf` は `atom` があれば null。
    `carryPick` は `atom` があれば**同じオブジェクト**を返し、分子の pick では `along` を引き継ぐ。
  - 分子の π の 2 本は `index` が `first` と `first + 1` のまま（`along` を付ければ V6-6 の境界ではどちらでも
    同じ向きの 1 本）。
- **`atomOrbitalWords(symbol, name, along: Along | null)`** → 「N の原子の 2p（結合の軸の向き）。結合する前の、
  原子ひとつの部屋です。」（`name` が `''` なら「N の原子の部屋」）。`name` は相関図の段の `name`（原子の
  段は `rung.name`、例 `2p`）から取れる。**記号は相関図の列の `heading`**（左 `columns[0]`、右は最後の列）。
- **新規 `components/orient.ts`**: `type Vec3 = [number, number, number]`、`interface CameraAxes { right; up;
  forward }`（`forward` は見ている向き、手前は `-forward`）、`directionOf(along, from: Vec3, to: Vec3,
  camera: CameraAxes): Vec3`（単位ベクトル。`axis` は `from → to`）。viewer が無いときの標準は
  `{ right: [1,0,0], up: [0,1,0], forward: [0,0,-1] }`（`orient.test.ts` の `STANDARD`）。
  **座標の単位は問わない**（Å のまま渡してよい。向きだけ使う）。
- **相関図（`scan.ts`）**: 原子の p の組は 1 段 3 本（`count: 3`）。段に **`lineLength`**（分子・原子の s は 20、
  原子の p は 12）を足し、**`CorrelationDiagram.tsx` は既にそれで線と当たり判定を描く**。原子の `picks` が
  埋まったので、**やること 4（原子の線の当たり判定）は済んでいる**（押すと今は App が `atom` を読まず
  分子の軌道を頼む ＝ O₂ ではエラー。やること 2 で直る）。`aria-label` は「O の原子の部屋、2p、結合の軸の
  向き」、分子の π は「…、π*、電子が 1 つ、HOMO、軸に垂直・画面の中」（「1 つめ」は消えた）。
- `CORRELATION_HINT` はまだ「まん中の線を押すと、その部屋の形を描きます。」で終わる（やること 5 で直す）。
