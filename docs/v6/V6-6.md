# V6-6 境界: 原子軌道と向きを Worker 越しに（`dft-wasm`・契約・`.wasm`）

**依存: V6-5**（`dft-core` の `molecular_oriented` / `atomic_column`。名前は V6-5 の
「V6-5 で入ったもの」を見る）

**目的**: 等値面の要求（`channel: 'orbital'`）に 2 つの任意の欄を足す。
`along?: [x, y, z]`（縮退の組を回す向き）と `atom?: number`（あれば分子の軌道ではなく、その
原子の自由原子の軌道。`orbital` はその原子の `atomLevels` の並びの添字）。UI はまだ使わない（V6-8）。

## 前提（今のコード）

- `crates/dft-wasm/src/lib.rs` の `Calculation::isosurface(&mut self, channel: &str, iso_level: f64,
  index: Option<usize>, spin: Option<String>) -> Result<IsoMesh, JsValue>`
  （`grep -n "pub fn isosurface"`）。`"orbital"` なら `self.orbital_grid(index, spin)` →
  `cut("orbital", grid, iso_level)`。
- `orbital_grid(index, spin)`（`grep -n "fn orbital_grid"`）は `signed_column` →
  `GridSpec::for_molecule` → `density::evaluate_orbital` で格子を作り、
  **`self.orbital: Option<(usize, SpinChannel, DensityGrid)>` に 1 本だけ持つ**（WASM の線形
  メモリは縮まないので 1 本）。同じ鍵ならしきい値の変更はただ。
- **`dft-wasm` は単位変換とシリアライズだけ。物理を書かない。** `along` は向き（単位ベクトル）で、
  Å と Bohr の変換は要らない（長さが変わっても向きは同じ）。ただし**長さ 3 でない・長さが ~0 は
  エラー**、正規化はここでしてよい（シリアライズの範囲）。
- Worker の契約は `web/src/worker/protocol.ts` が唯一の情報源（`grep -n "orbital\` and \`spin\` are
  for"` の周り、`isosurface` の要求の型）。`web/src/worker/dft.worker.ts` の
  `current.isosurface(` （`grep -n "current.isosurface("`）が呼ぶ。クライアントは
  `web/src/worker/workerClient.ts` の `async isosurface(`。
- `web/src/worker/engine.test.ts` はコミット済みの `.wasm` を実際に呼ぶ（`describe('the ladder of
  orbital levels'` が軌道の例）。

## やること

1. **`dft-wasm`**: `isosurface` に `atom: Option<usize>` と `along: Option<Vec<f64>>` を足す。
   `orbital_grid` の鍵を `(index, spin)` から enum に:
   `Molecular { index, spin, along: Option<[f64; 3]> }` / `Atomic { atom, orbital, along }`。
   `Atomic` は `atomic_column(&self.system, atom, orbital, along)`、`Molecular` は
   `molecular_oriented(...)`。**持つ格子は 1 本のまま**。返す `channel` はどちらも `"orbital"`。
   `atom` があるとき `spin` は無視（自由原子はスピンで分かれない）。
2. **`protocol.ts`**: 要求の型に `atom?: number` と `along?: [number, number, number]` を足し、
   コメントに意味（`atom` のときの `orbital` の数え方・`along` は向きだけで長さは問わない・
   縮退していない軌道では無視・格子は 1 本）。
3. **`dft.worker.ts`・`workerClient.ts`**: 2 つの欄をそのまま通す（`isosurface(channel, level,
   orbital?, spin?, atom?, along?)`）。
4. **`engine.test.ts`**（実物の `.wasm`）: N₂（軸を斜めに置く）を `scf` してから
   - `atom: 0, orbital: 1`（2s。N は 1s・2s・2p×3 の順）と、2p（`orbital: 2`）を
     `along` = 軸・垂直 で要求して、どれもメッシュが返る。
     2p は正と負の塊が 1 つずつ（`lobes`）。
   - 分子の π（はしごで `count === 2` の段）を `along` = 2 つの垂直方向で要求して、2 つの
     メッシュの頂点が違う（回っている）。
   - `along: [0, 0, 0]` と長さ 2 の配列はエラー、`atom` が範囲外はエラー。
   - 同じ要求でしきい値だけ変えると速い（今の軌道のテストと同じ見方でよい）。
5. `npm run build:wasm` → `web/src/wasm/` が変わる（コミットはユーザーに言われたとき。**CI の
   Linux ビルドとバイトが違うので、push したら `git pull`**）。

## V6-5 で入ったもの

どれも `dft_core::orbital`（`lib.rs` から再輸出はしていない。`dft-wasm` は既に
`use dft_core::orbital::{self, OrbitalInfo};` なので `orbital::…` で呼べる）。

- `orbital::molecular_oriented(system: &System, result: &ScfResult, orbital: OrbitalRef,
  along: Option<[f64; 3]>) -> DVector<f64>`。`None` なら `signed_column` と**同じ列**。
  縮退していない軌道は `along` があっても `signed_column`。**範囲外の `channel` / `index` は
  `signed_column` と同じく panic** するので、今の `orbital_grid` の範囲検査を先に通すこと。
- `orbital::atomic_column(system: &System, atom: usize, orbital: usize, along: Option<[f64; 3]>)
  -> Result<DVector<f64>, OrbitalError>`。長さは `system.basis.n_functions()`、原子の区画の外は
  厳密に 0、`uᵀ S u = 1`。
- `orbital::OrbitalError`（`Debug, Clone, Copy, PartialEq, Eq`、**`Display` は無い**）:
  `NoSuchAtom { atom, atoms }` / `NoSuchOrbital { orbital, orbitals }`。文言は境界で作る。
- `orbital::oriented(basis, overlap, set, along) -> DVector<f64>`（上の 2 つの中身）。`along` は
  正規化しなくてよい（中で割る）。**長さ 0 の `along` はエラーにせず組の最初の列を返す**ので、
  `[0, 0, 0]` を弾くのは境界の仕事（チケットのとおり）。σ の向きを渡された π の組も最初の列。
- `scf::guess::atomic_orbitals(z, kind) -> (System, OrbitalSet)`。**`atomic_levels(z, kind)` は
  その `energies` そのもので、列 i が `atomLevels` の i 番目**（偶奇で確かめた:
  `atomic_orbital_columns_follow_the_levels`）。だから要求の `orbital` は、その元素の
  `atomLevels` の配列の添字をそのまま渡せばよい（N は 0 = 1s、1 = 2s、2〜4 = 2p）。
- チケットの `atom_functions` は足していない。同じ意味の `BasisSet::atom_range(atom)` がある。
- `along` の座標系は分子の座標（Bohr でも Å でも向きは同じ）。自由原子は原点で解くが、
  デカルトの p 関数は置き場所に依らず同じ向きなので、分子の座標の向きをそのまま渡してよい。
