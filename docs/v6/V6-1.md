# V6-1 記録ツリーの並びを固定し、注意書きを段ごとに

**依存: なし**

**目的**: (1) 記録を選ぶ（開く）と、その分子がツリーの一番上に移る動きをやめる。
(2) 異性体の注意書きを、段ごとに正しい強さで言い分ける。

## 前提（今の動き）

- 並べ替えているのは App の `recordGroups`（`grep -n "const recordGroups" web/src/App.tsx`）:
  ```ts
  const recordGroups = useMemo(() => {
    const all = groupRecords(records);
    // A stable sort, so within each half the newest group stays first.
    return all.sort(
      (a, b) => Number(b.formula === currentFormula) - Number(a.formula === currentFormula),
    );
  }, [records, currentFormula]);
  ```
  記録を開くと `atoms` が変わり → `currentFormula` が変わり → その分子が先頭に来る。
  `openRecord` は記録を保存し直さない（`savedAt` は変わらない）。
- `groupRecords`（`web/src/records/log.ts`）は群を `latest`（群の中で最も新しい `savedAt`）の
  新しい順に返す。**`log.ts` は変えない**（ほかでも使う）。
- 木は `buildRecordTree(groups, pending)`（`web/src/records/tree.ts`）。`recordsOnly` が
  分子ごとに群をまとめ、**分子の順は「その分子の群が最初に出てきた順」**。候補だけの分子
  （`fresh`）は先頭に付く。段の順は `LEVEL_ORDER`（shape → measure → null）で固定。
  ファイル先頭のコメントに「the App puts the molecule on screen first」とある。
- `defaultExpanded(tree, { currentFormula, openId })` は画面の分子を開く。**これは残す。**
- 注意書きは `ISOMER_CAVEAT`（`web/src/components/records.ts`）1 つで、
  `RecordExplorer.tsx` の最後に `<p className="explorer-caveat">{ISOMER_CAVEAT}</p>`。
  テストは `records.test.ts` の `describe('what the section says the comparison is for'`
  （`'当てになりません'` を含むことを見ている → 書き換える）と F4 の検査（`FORBIDDEN`）。
- `levelLabel('shape')` は「形を探す」、`levelLabel('measure')` は「形を測る」
  （`components/level.ts`）。

## やること

1. **App**: 並べ替えを消す。`const recordGroups = useMemo(() => groupRecords(records), [records]);`
2. **`tree.ts`**: 分子の順を群の順から切り離す。**分子は「その分子のすべての記録の中で最も古い
   `savedAt`」の新しい順**（同じなら `formula` の順）。候補だけの分子（`fresh`）は今どおり先頭。
   分子の中の段・記録の並びは変えない。先頭コメントの該当文を直す。
3. **画面の分子の行に印**: `RecordTree.tsx` の `formulaRow` の `.tree-row` に、分子式が
   `currentFormula` のとき `current` クラス（`RecordExplorer` から `currentFormula` を渡す）。
   CSS は `.tree-row.current .tree-name { color: #3f8cff; }` 程度（`grep -n "\.tree-name"
   web/src/App.css`）。
4. **注意書き**: `ISOMER_CAVEAT` を段ごとの 2 文に替える（`ISOMER_CAVEATS: Record<ModelLevel,
   string>` と、群の段の一覧から出す文を返す `isomerCaveats(levels)`）。文言:
   - shape: `「形を探す」の記録: つながり方が違う分子（異性体）どうしでは、どちらが安定かが逆に
     出ることがあります。くらべるときは「形を測る」で計算してください。`
   - measure: `「形を測る」の記録: つながり方が違う分子（異性体）どうしでも、どちらが安定かの
     順は、これまで試した組ではすべて合っています。ただし差の大きさは実際より小さく出ることが
     あります。`
   - 段の名前は `levelLabel` から組み立てる（直書きしない）。
   - **出すのはツリーにある段だけ**（群の `level` を集める。`null` は無視）。記録が 1 件も
     無ければ何も出さない。1 つの段につき `<p className="explorer-caveat">` を 1 つ。
   - 定数のコメントに根拠を書く: dev-notes「v3-0 の実測」の表（5 組。「形を探す」は C₃H₆ と
     C₂H₆O の 2 組で逆、「形を測る」は 5 組とも順序が合い、大きさは C₃H₆ −5.4 / 実験 −32.9）。
5. **テスト**（`records.test.ts`・`tree.test.ts`）:
   - 古い記録の分子と新しい記録の分子 → 新しいほうが先。**古い分子に新しい記録を足しても
     順が変わらない**（ここが今の不具合の本体。`latest` の順と違うことを確かめる入力にする）。
   - 候補だけの分子は先頭のまま。
   - `isomerCaveats(['shape'])` は 1 文、`['shape','measure']` は 2 文で shape が先、`[]` は空。
   - 文に「異性体」、shape の文に「逆に」、measure の文に「合って」を含む。F4 の検査を新しい
     文にも掛ける。
