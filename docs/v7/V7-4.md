# V7-4 イオンのボタンと計算をつなぐ（App・探索）

**依存: V7-2, V7-3**（`workerClient` の `charges` と、`ion.ts` / `atoms.ts`。それぞれの
「V7-n で入ったもの」を見る）

**目的**: 計算タブで**選んだ原子をイオンに変える**ボタンを出し、その電荷を「安定な形にする」
「この形のまま計算」「いろいろな形を試す」まで通す。陰イオンの注意書きと、イオンがあるときの
差密度の言葉を出す。**3D の印（V7-5）・記録（V7-6）・スキャンと相関図（V7-7）はまだ。**

## 前提（今のコード）

- 計算タブの JSX: 「配置する元素」の `PeriodicPicker` の下に `削除` / `全消去` の
  `ActionGrid columns={2}`（`grep -n "削除 names no element" web/src/App.tsx`）、その下が
  `<h2>次の計算</h2>`。選んだ原子は `const [selected, setSelected] = useState<number | null>`
  （編集モードだけ。観測モードに入ると `null`）。
- 原子を変える操作は `setAtoms(...)` と `invalidateResult()`。`handBuilt` は**位置の出どころ**
  （電荷を変えても位置は変わらないので触らない）。計測（`setMeasured`）は原子の並びが変わる
  ときだけ消す規約なので、電荷の変更では消さない。
- 計算の入口: `const calculate = useCallback(` と、`.optimize(` を呼ぶ緩和
  （`grep -n "toWorkerArrays" web/src/App.tsx`）。どちらも `toWorkerArrays(structure)` を使う。
- 探索: `web/src/search/pool.ts` の `CandidateRequest { id, batch, z, built, start }` と
  `#start(slot, candidate)` の `slot.client.optimize(candidate.z, candidate.start, …,
  SEARCH_LEVEL)`。候補は `web/src/search/candidates.ts` の `candidateAsBuilt` /
  `nudgedCandidates`（`CandidateSource { z, xyz, covalentRadius }`）が作る。App で候補を画面に
  戻すのは `atomsOfFlat`（V7-3 で `atomsFromFlat` に）。
- 差密度の説明は `explainChannel`（`components/density.ts`）を観察タブが呼ぶ
  （`grep -rn "explainChannel(" web/src --include=*.tsx`）。
- 異性体の注意書き（`isomerCaveats`）が注意書きの前例（`components/records.ts`）。

## やること

1. **ボタン**: 削除 / 全消去の行の下に `Segmented`（`ION_GROUP_LABEL` / `ION_OPTIONS`）。値は
   選んだ原子の `charge ?? 0`、無効は `chargeChoices(atoms, selected)`。**原子を選んでいなければ
   全部無効**（消さない）。押したら `setAtoms` で電荷だけ変え、`invalidateResult()`。
   計算中は他の編集と同じく固める。
2. **計算に通す**: `calculate` と緩和の `.optimize(` に `toWorkerArrays` の `charges` を
   最後の引数で渡す。**`withPositions` / `atomsFromFlat` で電荷が落ちない**ことを、緩和の後の
   `atoms` で確かめる。
3. **探索**: `CandidateRequest` に `charges: Int8Array`、`candidateAsBuilt` / `nudgedCandidates` は
   `CandidateSource` の `charges` をそのまま写す（揺らすのは位置だけ）。`#start` が `optimize` の
   最後に渡す。候補を画面に戻すときも電荷を付ける。`pool.test.ts` / `candidates.test.ts` に
   「電荷が候補と要求に写る」を足す。
4. **陰イオンの注意書き**: `hasAnion(atoms)` のとき `ANION_CAVEAT` をイオンのボタンの下に弱い
   文字で 1 段落。観察タブにも、数値の近くに 1 か所（置き場所は今の `isomerCaveats` か
   状態の近くの、**縦に積む**ところ）。
5. **差密度の言葉**: イオンがあるとき（`atoms.some(a => (a.charge ?? 0) !== 0)`）は V7-3 の
   イオン用の説明を出す。**判定は画面の原子で**（`hasPi` と同じく計算のたびに消えないように）。
6. **ブラウザ**（`read_page` / `javascript_tool`）: H₂O を置いて 1 つの H を選び「+ にする」→
   「この形のまま計算」が収束する。H ひとつだけのとき「+ にする」が無効。OH の O を「− にする」で
   注意書きが出る。`console.debug` の `ScfOutcome.charge` が合計と一致。「安定な形にする」の後も
   電荷が残っている（`atoms` を React の外から見る手口は dev-notes「P7 の実装メモ」にある）。

## V7-2 で入ったもの

- **`workerClient` の 4 つのメソッドは最後に `charges?: Int8Array`**（原子と同じ並び、省略＝全部中性。
  既定を置くのは `dft-wasm` の `atom_charges` の 1 か所だけ）:
  - `scf(z, xyz, onProgress?, level?, charges?)`
  - `optimize(z, xyz, onStep, onProgress?, budgetMs?, level?, charges?)`（前面は `budgetMs` に
    `undefined` を渡して飛ばす。プールの `#start` は今の `SEARCH_LEVEL` の後ろに足すだけ）
  - `scan(z, from, to, points, onPoint, budgetMs?, charges?)`（`budgetMs` を飛ばすなら `undefined`）
  - `atomLevels(z, charges?)`
  `protocol.ts` の 4 つの要求にも `charges?: Int8Array`。`toWorkerArrays` の `charges` をそのまま渡せる。
- **`ScfOutcome.charge` は指定した合計がそのまま返る**（省略なら 0）。`multiplicity` / `attempts` は
  診断用のまま。
- **エラーの文言**（promise が reject する。`GeometryError` の `{:?}` は流さない）:
  - 長さ違い →「charges must have one entry per atom: expected N, got M」
  - 電子 0（H ひとつに +1、H₂ の両方に +1）→「the total charge leaves no electrons」
  - 1 原子に無理な電荷（−2 以下・`z` を超える +・He/Ne/Ar の −）→
    「atom I (element Z) cannot carry a charge of C」（`I` は `z` の中の位置）
  - UI の決まり（−1/0/+1・合計 −2〜+2・`chargeChoices`）で押せなくしてあれば、どれも起きないはず。
- 同じ形なら **H⁺ で置いても O⁺ で置いても `scf` のエネルギーはビット単位で同じ**、差密度だけが違う
  （`engine.test.ts` の H₃O⁺ で確認済み）。`optimize` も毎歩 `charges` を引き継ぐ（Rust の側で）。

## V7-3 で入ったもの

- **型**: `scene/viewer.ts` の `export type AtomCharge = -1 | 0 | 1` と `SceneAtom.charge?: AtomCharge`。
  **中性の原子は `charge: 0` ではなく欄そのものを持たない**（`atoms.ts` がそう組む）。電荷を変えるときも
  0 なら欄を消すと、v6 までの原子と `toEqual` で比べられる（必須ではない。どこも `?? 0` で読む）。
- **`toWorkerArrays(atoms)` は `{ z, xyz, charges }`**（`charges: Int8Array`、全部 0 でも付く）。
  `workerClient` の最後の引数にそのまま渡せる。
- **`molecules/atoms.ts`**: `withPositions(atoms, xyz)`（電荷を保つ。緩和の 2 か所はもう import 済み）と
  `atomsFromFlat(z, xyz, charges?)`。**App の `atomsOfFlat` はまだ `(z, xyz)` だけで、中身は
  `atomsFromFlat(z, xyz)`**（`grep -n "atomsOfFlat" web/src/App.tsx`）。候補を戻す
  `atomsOfFlat(candidate.z, candidate.start)` は**まだ中性に戻る**ので、3 番で `charges` を足して渡す
  （`atomsOfRecord` の分は V7-6）。
- **`components/ion.ts`**（テストは `ion.test.ts`）:
  - `ION_GROUP_LABEL`（`'イオン'`）、`ION_OPTIONS: SegmentedOption<IonChoice>[]`
    （`IonChoice = 'minus' | 'neutral' | 'plus'`、文字は「− にする」「中性」「+ にする」）。
  - **`Segmented` の値は文字列なので変換を挟む**: `choiceOfCharge(atom.charge)`（`undefined` は
    `'neutral'`）と `chargeOfChoice(choice): AtomCharge`。
  - **無効の渡し方**: `SegmentedOption` に `disabled?: boolean` を足した（`controls.tsx`、群の
    `disabled` と OR）。**`ionOptions(atoms, index)` が無効を埋めた選択肢を返す**ので
    `<Segmented label={ION_GROUP_LABEL} options={ionOptions(atoms, selected)} value={choiceOfCharge(…)}
    onChange={…} disabled={計算中} />` でよい。原子を選んでいないときは `options={ION_OPTIONS}` +
    `disabled`（`ionOptions` は範囲外の添字で `RangeError` を投げる）。可否だけ欲しければ
    `chargeChoices(atoms, index): Record<IonChoice, boolean>`。
  - `totalCharge(atoms)`・`electronCount(atoms)`・`hasAnion(atoms)`・**`hasIons(atoms)`**（5 番の判定は
    これを使う）・`ANION_CAVEAT`・`MIN_TOTAL_CHARGE`/`MAX_TOTAL_CHARGE`（−2/2）。
- **差密度の言葉**: `explainChannel(request, mesh, hasIons?)` の**3 つめ**（省略＝中性の文言）。
  観察タブの呼び出し（`grep -n "explainChannel(" web/src/App.tsx`）に `hasIons(atoms)` を足すだけ。
  変わるのは差密度（名指しと「結合に寄与する電子」が差密度で返ったとき）の文だけ。
