# V7-0 実測: イオンの参照値・スキャンの限界・陰イオンの文言

**依存: なし**

**目的**: 後のチケットが頼る数字と参照値を先に作る。(1) イオンの SCF の参照値（V7-1 のテスト用）、
(2) 荷電二原子の距離スキャンをどこで切るか（V7-7）、(3) 陰イオンの注意書きの文言（V7-3）、
(4) 1 原子・合計の電荷の上限（V7-3）。**Rust・TS のコードは残さない**（測るスクリプトは
スクラッチパッドに置く）。残すのは `gen_reference.py` の関数 1 つ・その JSON・dev-notes の 1 節。

## 前提（今のコード）

- 電荷は `dft_core::molecule::Molecule.charge`（合計、`i32`）。`multiplicity` と組で
  `spin_occupation()` が α/β の電子数を出す。`driver::solve` は今は中性から解き始める
  （`grep -n "fn rounds" crates/dft-core/src/driver.rs`）ので、**測るときは `driver` を通さず**
  `molecule.charge` / `multiplicity` を直接置いて `scf::run_restricted` / `run_unrestricted`、
  最適化は `opt::relax(system, &Options::default(), None, &mut |_| true, &mut |_| {})`。
  `opt::bond_angle` は**度で返す**（ラジアンではない）。
- 測るのはネイティブの example でよい（`crates/dft-core/examples/` に一時ファイルを置いて
  `cargo run --release -q --example 名前`、**終わったら消す**）。
- 参照値は `scripts/gen_reference.py` だけが作る。`make_mol(atoms, unit, basis, cart, spin)` は
  `mol.charge = 0` 固定（`grep -n "def make_mol"`）。PySCF は `.venv`
  （`.venv/bin/python -c "import sys; sys.path.insert(0,'scripts'); import gen_reference as g; g.関数()"`
  で**その関数だけ**回す。`main()` を丸ごと回すと他の JSON が収束ノイズで揺れる）。
- 相談のときの実測（dev-notes「v7 の相談での実測」）: 陽イオンは形も含めて素直、陰イオンは
  最高被占軌道が正、H₂⁺ は 4 Å で 0.09 Ha 低く 8 Å で跳ぶ、HeH⁺ は正しく He + H⁺ に分かれる。

## やること

1. **参照値**: `make_mol` に `charge: int = 0` を足し（既定 0 で既存の呼び出しは変えない）、
   `ion_reference()` を足して `crates/dft-core/tests/data/scf_ions.json` を作る。
   中身は `scf_reference` と同じ形で、少なくとも H₃O⁺・NH₄⁺・H₃⁺・HeH⁺（陽イオン、一重項）、
   OH⁻・F⁻（陰イオン）、H₂⁺（二重項、`unrestricted_payload` の形）。STO-3G。幾何は
   `GEOMETRIES` に足す（相談で使った形: dev-notes の節にある）。`main()` にも 1 行足す。
   **その関数だけ回し**、`git status` で他の JSON が動いていないことを見る。
2. **エンジンと参照値の突き合わせ**（上の JSON を読む一時 example で）: 全エネルギーが既存の
   中性の参照値と同じ許容差（`crates/dft-core/tests/` の SCF のテストが使う値）で合うか。
   合わなければ先にどちらが正しいかを確かめる（CLAUDE.md）。
3. **荷電二原子のスキャンの上端**: H₂⁺ を 0.5〜6 Å で 0.25 Å ごと。**1 電子系の HF は基底の中で
   厳密**なので、PySCF の HF（同じ STO-3G）との差を距離ごとに取り、差が井戸の深さの 10% を
   超える最初の距離を「平衡距離の何倍か」で出す。HeH⁺・He₂⁺・N₂⁺・O₂⁺・O₂⁻・OH⁻ も同じ範囲で
   エンジンだけ回し、曲線が跳ぶ・収束しなくなる距離を平衡距離の倍率で表にする。
   これらから `rangeAround` の上端の倍率（中性は 1.8）を荷電の組のために 1 つ決める
   （例: 1.4）。**スキャンは状態を最短距離で 1 回選んで固定**（`scan.rs`）なので、その流れで回す
   こと（各点で状態を選ばない）。スキャンの一時コードは `scan::distance_scan` を使ってよいが、
   今は電荷を渡す引数が無い: `solve_at`（`grep -n "fn solve_at" crates/dft-core/src/scan.rs`）の
   中身を一時 example に写して `molecule.charge` を置く。
4. **陰イオンの注意書き**: OH⁻・F⁻・Cl⁻・CN⁻・NH₂⁻ の最高被占軌道の符号を STO-3G と 6-31G\* で
   表にする。全部正なら文言は「陰イオンの余分な電子は、本当はこの分子に留まりにくいものです。
   この計算では、留まっているように見えます。」の趣旨で、**数値・基底の名前を出さない**（F4）。
   案を 1〜2 文で決めて dev-notes に書く（V7-3 がそのまま `.ts` に置く）。
5. **電荷の上限**: CH₄ の H を 2 つ、3 つ + にしたもの（CH₄²⁺・CH₄³⁺）と、SO₄²⁻（S と O 4 つ、
   O 2 つを −）を一点計算と最適化で回し、収束するか・形が壊れる（原子が飛ぶ）かを見る。
   合計の上限を決める（案: −2〜+2）。**1 原子は −1 / 0 / +1 のまま**。
6. **ついでに**: Na⁺・Cl⁻・O⁻・H⁻ の自由原子を `Occupation::SphericalAverage` で解けるか
   （V7-1 の差密度の基準に要る。今の `guess::atomic_orbitals` は中性だけ）。一時 example で
   `Molecule.charge` を置いて同じ設定で回し、収束と `tr(D S)` を見る。
