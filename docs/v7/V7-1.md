# V7-1 エンジン: 原子ごとの電荷、指定どおりに解く、イオン基準の差密度（`dft-core`）

**依存: V7-0**（`scf_ions.json` と、自由イオンが解けるかどうか。「V7-0 で入ったもの」を見る）

**目的**: `dft-core` が原子ごとの電荷を持ち、(1) 合計を**指定どおりに**解き（`driver` が電荷を
変えない）、(2) SAD の初期値と差密度の基準を**置いたとおりのイオン**で作り、(3) 自由原子の
準位・軌道もイオンで出せるようにする。境界（`dft-wasm`）はまだ触らない（V7-2）。

## 前提（今のコード）

- `crates/dft-core/src/molecule.rs`: `Atom { z, pos }`（Bohr）、`Molecule { atoms, charge,
  multiplicity }`。構造体リテラルで `Molecule { … }` を書いているのは `Molecule::new` と
  `driver.rs` の `..molecule.clone()` の 2 か所だけ（`grep -rn "Molecule {" crates`）。
  `Atom { … }` のリテラルは約 60 か所あるので、**`Atom` には欄を足さない**。
- `crates/dft-core/src/driver.rs`: `solve` → `rounds(molecule, options)` が
  `Molecule { charge: 0, ..}` から基底の多重度を取り、一重項と三重項（または二重項）→ 同じものを
  重いダンピングで → 高い多重度 → **最後の手段で ±1**（`try_charges`）。`scan.rs` の
  `distance_scan` は最短距離で `driver` に状態を選ばせて固定する（`solve_at` が
  `molecule.charge = state.charge`）。
- `crates/dft-core/src/scf/guess.rs`: `superposition_of_atomic_densities(system)` は元素ごとに
  `atomic_density(z, kind)` をキャッシュして対角の区画に置く（**中性原子**。コメントに「荷電分子
  では跡が中性の電子数になり、SCF が数回で直す」）。`atomic_orbitals(z, kind) -> (System,
  OrbitalSet)` が球平均（`Occupation::SphericalAverage`）で自由原子を解く。`atomic_levels(z,
  kind)` はその `energies`。`orbital::atomic_column`（V6-5）もこれを読む。
- `crates/dft-core/src/bonding.rs`: `channel_density` の `Deformation` が
  `result.density - guess::superposition_of_atomic_densities(system)`（`grep -n "superposition"`）。
  テスト `a_non_planar_molecule_falls_back_to_the_deformation_density` が `tr(ΔD S) ≈ 0` を見る。
- `opt::relax` は毎歩 `system.molecule.clone()` から新しい位置の `System` を組む
  （`grep -n "molecule.clone()" crates/dft-core/src/opt/mod.rs`）ので、`Molecule` の欄は自然に
  引き継がれる。

## やること

1. **`Molecule` に原子ごとの電荷**: `atom_charges: Vec<i32>`（長さ = 原子数、既定は全部 0）。
   `Molecule::new` / `from_angstrom` は 0 で埋める。`with_atom_charges(self, charges) ->
   Result<Self, GeometryError>` のような組み立てで**合計を `charge` に入れる**（長さ違い・電子が
   0 以下は `GeometryError`）。`validate` に長さの検査。**`charge == atom_charges の和` を
   不変条件にする**（`driver` がもう電荷を変えないので保てる）。名前は実装で決めてよい。
2. **`driver`**: `rounds` の出発を `Molecule { charge: 0, ..}` ではなく**分子の電荷のまま**に
   （`SpinState.charge` はいつも `molecule.charge`）。**±1 の段（`try_charges`）を取り除く**
   （`DriverOptions` の欄ごと。`driver.rs` のテスト「The charged states are the last thing
   tried」も消す）。モジュール先頭のコメントの「Charge is the easy half」の段落を書き直す。
   `scan.rs` も同じく分子の電荷のまま（`distance_scan` に電荷 2 つを渡す引数を足す。
   `[z1, z2]` と同じ並びの `[i32; 2]`）。
3. **イオンの自由原子**: `atomic_orbitals(z, kind)` を `(z, charge, kind)` に。球平均のまま
   電荷を置いて解く。**電子が 0（H⁺・He²⁺ など）は SCF を回さず、密度 0・軌道は
   コア・ハミルトニアンの固有ベクトル**（Jacobi、`scf/linalg.rs`）。V7-0 で解けなかった
   イオンがあれば、その扱いは「V7-0 で入ったもの」に従う。`atomic_levels`・`atomic_column`
   （`orbital.rs`）も電荷を受け取る。
4. **SAD と差密度の基準を置いたとおりのイオンで**: `superposition_of_atomic_densities` の
   キャッシュの鍵を `(z, charge)` に。**電子数が `molecule.n_electrons()` とちょうど合う**
   ようになるので、先頭のコメント（「中性の電子数になる」）を書き直す。
5. **テスト**（参照値は `scf_ions.json` と独立な経路だけ）:
   - `scf_ions.json` の各イオンが参照値と合う（既存の中性の SCF のテストと同じ許容差）。
   - `driver::solve` が H₃O⁺（O と H 3 つ、H の 1 つが +1）で `state.charge == 1` を返し、
     どの `Attempt` も電荷 1（電荷を変えていない）。
   - 最適化で H₃O⁺ が三角錐、NH₄⁺ の 4 つの N–H が等しい（許容差は既存の最適化のテストと同じ）。
   - SAD の `tr(D S)` が H₃O⁺（H⁺ 入り）・OH⁻（O⁻ 入り）・NaCl（Na⁺ と Cl⁻）で電子数と一致。
   - 差密度の `tr(ΔD S) ≈ 0` が H₃O⁺（H⁺ 入り）で成り立つ。**同じ H₃O⁺ を「O⁺ と中性の H 3 つ」
     で置くと、SCF の答えは同じ（エネルギーが 1e-8 以内）で差密度だけが違う**（原子ごとの
     電荷が SCF には効かず基準にだけ効くことの確認）。
   - 電子 0 の自由原子（H⁺）の密度が 0、準位の数が基底関数の数。
   - 既存の中性のテストが全部そのまま通る（中性では何も変わらない）。

## V7-0 で入ったもの

（実測の全体は dev-notes「v7-0 の実測」。）

- **`crates/dft-core/tests/data/scf_ions.json`**: 形は `scf_open_shell.json` と**同じ**
  （`{functional, basis: "sto-3g", grid_level, systems: [...], atoms: [...]}`、各要素は
  `unrestricted_payload` の `{key, charge, multiplicity, n_alpha, n_beta, unrestricted, atoms: [{z, pos
  (Bohr)}], nbf, n_electrons, nuclear_repulsion, energy, e_core, e_coulomb, e_xc, mo_energies: [[α], [β]],
  density_matrix: [[α], [β]], spin_squared, energy_grid_level_3}`。閉殻は RKS を 2 つの等しい列で書いたもの）。
  **`tests/common/mod.rs` の `OpenShellReferences` / `OpenShellReference::molecule()` がそのまま読める**
  （`charge` と `multiplicity` を置き、`spin_occupation()` を照合する）。チケットの「`scf_reference` と
  同じ形」から変えたのは、電荷を持つ形がこちらだけだから。
  - `systems`: `h3o_plus`・`nh4_plus`・`h3_plus`・`heh_plus`（+1、一重項）、`oh_minus`（−1、一重項）、
    `h2_plus`（+1、二重項、`unrestricted: true`）。
  - `atoms`（閉殻の自由イオン、中心は原点）: `h_minus`・`li_plus`・`f_minus`・`na_plus`・`cl_minus`。
    球平均（`Occupation::SphericalAverage`）の Fine で解くと 1e-7 以内で合う ＝ 既存の
    `closed_shell_atoms_match_the_reference` と同じ形のテストが書ける。
  - 今のエンジン（Medium、`run_unrestricted` / `run_restricted`）で**全部 `GRID_TOLERANCE` 1e-4 の内側**
    （最大 HeH⁺ の +1.5e-5 Ha）。参照の密度での項ごとも同じ。**エンジンは何も直さずに合う。**
  - 原子ごとの電荷は参照値に**入っていない**（PySCF は合計しか知らない）。H₃O⁺ は「H の 1 つが +」でも
    「O が +」でも同じ参照値に合うはず、がテストの形。
- **自由イオンは解ける**: 今の `atomic_orbitals` と同じ設定（Coarse、`InitialGuess::Core`、球平均、
  80 回、ダンピング 8 回）で `Molecule.charge` を置くと、Z = 1〜18 の ±1（H⁺ を除く）が両基底で収束し
  `tr(D S)` が電子数と一致（Na⁺・Cl⁻・O⁻・H⁻ も）。**例外は STO-3G の He⁻・Ne⁻・Ar⁻ の 3 つ**:
  殻が埋まっていて余分な電子の入る関数が無く、**`converged: true` のまま `tr(D S)` が 1 足りない**
  （黙って電子を落とす）。扱い: **He・Ne・Ar に −1 は付けられない**ことにする（貴ガスの陰イオンは
  実在もしない。V7-3 のボタンも同じ規則で無効）。`with_atom_charges`（仮称）が
  `GeometryError` で拒む。1 原子 −1 までなら、この規則で STO-3G でも分子全体の基底に必ず電子が入る。
  電子 0（H⁺）はチケットどおり SCF を回さない。
- **スキャン（`scan.rs`）への頼み**: 第 3 周期の π に穴が 1 つある陽イオン（Cl₂⁺・HCl⁺）は**既定の
  SCF ではどの距離でも収束せず、曲線が丸ごと穴**になる（Al・Si 原子と同じ占有の振動）。`solve_at` で
  **収束しなかった点を `DriverOptions::default().persistent_scf` で解き直す**と、上端（V7-7 の 1.4 倍）
  まで穴が無くなる（O₂⁺ の 1.35 倍の穴も埋まる）。**解き直しは `molecule.charge != 0` のときだけ**に
  すれば中性のスキャンは 1 ビットも変わらない（「HF は 1.89 Å から先で落ちる」も今のまま）。値段は
  Cl₂⁺ 27 点がネイティブで 17.5 秒（全部穴）→ 23.9 秒、H₂⁺・O₂⁺ はほぼ変わらない。
  テストは「Cl₂⁺（+1）を 0.7〜1.4 × 2.08 Å で走らせると全点収束」の形で書ける（NaCl⁺ は解き直しても
  穴が残るのでテストに使わない）。
- **正四面体の CH₄⁺ は解けない**（知っておくこと。直さなくてよい）: 二重項は既定・粘る設定・
  レベルシフト 1.0・強いダンピングのどれでも収束しない（3 重に縮退した軌道に穴が 1 つ）。この
  チケットの `driver`（二重項 → 粘る二重項 → 高い多重度）だと **0.64 Ha 上の四重項**で「収束」し、
  最適化で分子が崩れる。CO₂⁺・ベンゼン⁺（2 重の縮退）は粘る設定で解ける。高い多重度の段は中性でも
  同じ働きなので、このチケットでは変えず、`driver` のテストにも使わない（V7-8 で画面を見る）。
