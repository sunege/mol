# V7-6 記録: 原子ごとの電荷・ファイル version 2・見出し

**依存: V7-4**（電荷が計算と候補まで通っていること。「V7-4 で入ったもの」を見る）

**目的**: 記録が原子ごとの電荷を持ち、開けばイオンのまま戻り、ツリーの見出しが H₃O⁺ になる。
ファイルは version 2 で書き、version 1 は全部中性として読む。

## 前提（今のコード）

- `web/src/records/record.ts`: `StructureRecord { id, savedAt, name, model, formula, z, built,
  trajectory, stepEnergies, final, outcome, source, batch? }`。`formula` は `hillFormula(z)`
  （電荷なし）。`comparisonKey(record)` は `${model}|${outcome.charge}|${formula}`（**もう電荷
  込み**）。`createRecord(draft, …)` が作る。`defaultRecordName(formula, savedAt)` が名前の既定。
- `web/src/records/file.ts`: `LOG_VERSION = 1`、`readStructureLog` は `parsed.version !==
  LOG_VERSION` を `{ kind: 'version' }` で拒否。先頭のコメントに「形が変わったら、古い version の
  読み方はここに入る」。`checkRecord` が 1 件ずつ検査し、**1 件でも駄目なら全部拒否**。
- `web/src/records/store.ts`（IndexedDB）には v6 までの記録が `charges` 無しで入っている。
- `web/src/records/tree.ts`: 分子のノードは `formula` で束ねる（`kind: 'formula'`、
  `formulaId(formula)`）。先頭のコメントに「電荷だけ違う群は見出しが同じ（F4 で出さない）」、
  候補について「電荷は解くまで分からない」（`grep -n "charge" web/src/records/tree.ts`）。
  **どちらも v7 で嘘になる**（電荷は出すし、候補の電荷は要求から分かる）。
- App: `const currentFormula = … hillFormula(atoms.map((a) => a.z), symbolOf)`
  （`grep -n "currentFormula"`）がツリーの「画面の分子」の行の目印。`atomsOfRecord` が記録を
  画面の原子に戻す。
- V7-3 の `formulaWithCharge(formula, total)`、`totalCharge(atoms)`、`atomsFromFlat(z, xyz, charges?)`。

## やること

1. **記録の形**: `StructureRecord` に `charges?: number[]`（原子と同じ並び。**省略＝全部中性**、
   読むのは `chargesOf(record)` の 1 か所だけ）。`createRecord` は**いつも書く**。`formula` は
   Hill 式のまま（電荷なし）。
2. **見出し**: 分子のノードの見出しと束ねる鍵を `formulaWithCharge(formula, outcome.charge)` に
   （**合計は `outcome.charge` から**。v6 の `driver` が ±1 で解いた記録がもしあっても、見出しが
   計算と合う）。`defaultRecordName` も電荷付きの式で。候補は要求の `charges` の合計から。
   tree.ts の先頭と候補のコメントを書き直す。
3. **ファイル**: `LOG_VERSION = 2`。version 1 は受け付けて `charges` 無し（＝中性）として読む。
   version 2 は `charges` が**必須**（長さ = 原子数、各 −1/0/+1、`Σcharges === outcome.charge`）。
   それ以外の version は今までどおり拒否。先頭のコメントを更新。`file.test.ts` に:
   v1 が開ける、v2 の往復、v2 で `charges` が無い・長さ違い・合計が合わない、がそれぞれ拒否。
4. **開く**: `atomsOfRecord` が `chargesOf(record)` を渡す。記録の等値面の一点計算
   （`levelOfRecord` のところ）にも電荷が要る: `toWorkerArrays` から来ているか確かめる。
5. **画面の分子の目印**: `currentFormula` を `formulaWithCharge(hillFormula(…), totalCharge(atoms))` に。
6. **ブラウザ**: H₃O⁺ を計算して記録 → ツリーに「H₃O⁺」の分子の行、中性の H₃O は別の行。
   記録を開くと H が + のまま（`atoms` を見る）。書き出したファイルの `version` が 2。
   v6 の書き出しファイル（`docs/C₃H₆-記録-20260920-1859.json` が version 1 の実物）を読み込める。

## V7-3 で入ったもの

- `components/ion.ts`: **`formulaWithCharge(formula: string, total: number): string`**
  （`hillFormula` の後ろに `chargeSuffix(total)` を付けるだけ: `⁺` `⁻` `²⁺` `²⁻`、0 は空）と
  `totalCharge(atoms: readonly SceneAtom[]): number`。
- `molecules/atoms.ts`: **`atomsFromFlat(z, xyz, charges?: ArrayLike<number>)`**（0 と省略は電荷の欄
  無し、`charges` の値は検査せず `AtomCharge` として付ける ＝ 検査はファイルを読む側で）。
  App の `atomsOfFlat` の `useCallback` は**まだ `(z, xyz)` だけ**で中身が `atomsFromFlat(z, xyz)`。
  `atomsOfRecord` から `chargesOf(record)` を通すには `atomsOfFlat` に 3 つめを足す
  （候補の分は V7-4 が足しているはず。`grep -n "atomsOfFlat" web/src/App.tsx` で確かめる）。
- `toWorkerArrays(atoms)` は `charges: Int8Array` も返す（記録の等値面の一点計算にそのまま渡せる）。

## V7-4 で入ったもの

- **候補は電荷を持つ**: `CandidateRequest.charges: Int8Array`（必須、`z` と同じ並び。`search/pool.ts`）。
  `candidateAsBuilt` / `nudgedCandidates` は `CandidateSource.charges` をそのまま写し、`#start` が
  `optimize` の最後に渡す。**2 番の「候補は要求の `charges` の合計から」は `candidate.charges` を足せばよい**
  （`Candidate extends CandidateRequest`）。
- `atomsOfFlat` は **`(z, xyz, charges?)`** になった（中身は `atomsFromFlat(z, xyz, charges)`）。
  `atomsOfRecord` は**まだ `atomsOfFlat(record.z, xyz)`** のまま ＝ 4 番で `chargesOf(record)` を 3 つめに。
- **記録を作る 2 か所は電荷をまだ書かない**（1 番で足す）: 探索の `onFinished` の
  `createRecord({ z: Array.from(candidate.z), built: …` と、緩和の `createRecord(` の
  `built: Array.from(xyz)`（`grep -n "createRecord(" web/src/App.tsx`）。緩和の側は `const { z, xyz,
  charges } = toWorkerArrays(original)` がもう手元にある。
- **記録の等値面の一点計算（`solveForSurface`）は `toWorkerArrays(structure)` の `charges` を渡している**。
  開いた記録の原子が電荷を持てば（4 番）そのまま効く。
- **V7-4〜V7-6 の間の穴**: 今はイオンの結果も中性の記録として保存され、**ツリーでは中性の群に並ぶ**
  （`comparisonKey` は `outcome.charge` 込みなので谷・順位は混ざらないが、見出しが同じ）。V7-4 の確認で
  ユーザーの IndexedDB に H₂O⁺（「H₂O」の群、10:36 ごろ）と OH⁻（「HO」、10:37 ごろ）の記録が入った。
