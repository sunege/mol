# V7-2 境界: 原子ごとの電荷を Worker 越しに（`dft-wasm`・契約・`.wasm`）

**依存: V7-1**（`Molecule` の組み立て方と新しい引数の並び。「V7-1 で入ったもの」を見る）

**目的**: `scf` / `optimize` / `scan` / `atomLevels` の要求に**任意の `charges`**（原子ごとの電荷、
`Int8Array`、原子と同じ並び）を足す。**省略＝全部中性**で、その既定を置くのは `dft-wasm` の
1 か所だけ（段の `level` の省略＝`'shape'` と同じ形）。UI はまだ使わない（V7-4）。

## やること

1. **`dft-wasm`**: 4 つの関数の**最後に** `charges: Option<Vec<i32>>`（JS では `Int8Array`
   か省略）。`None` は全部 0。`build_molecule(z, xyz, charges)` が V7-1 の組み立てを呼ぶ
   （長さ違い・電子 0 は `JsValue` のエラー。文言は「charges must have one entry per atom」
   「… leaves no electrons」の趣旨で、**`GeometryError` の `{:?}` をそのまま流さない**）。
   `scan` は 2 つ、`atomLevels` は `z` と同じ長さ。**物理を書かない**（合計を取るのも V7-1 の
   組み立ての中）。
2. **`protocol.ts`**: 4 つの要求に `charges?: Int8Array`。コメントに「原子ごとの電荷（−1/0/+1 は
   UI の決まりで、境界は検査しない）、省略＝中性、SCF が使うのは合計だけ、原子ごとの値は差密度の
   基準・自由原子の準位と軌道に効く」（**初期値には効かない**。V7-1 で入ったもの）。**`ScfOutcome.charge` のコメントを書き換える**: もう
   エンジンが選ぶものではなく「指定した合計がそのまま返る」。`multiplicity` は診断用のまま。
3. **`dft.worker.ts`・`workerClient.ts`**: `charges` をそのまま通す。クライアントの 4 つの
   メソッドは**最後の任意の引数**に `charges?: Int8Array`（呼び出し側は V7-4 まで変えない）。
4. **`engine.test.ts`**（実物の `.wasm`）:
   - H₃O⁺（H の 1 つに +1）を `scf` → `outcome.charge === 1`、収束。
   - 同じ形の中性の H₃O（ラジカル）とエネルギーが違う（電荷が本当に効いている）。
   - H₃O⁺ の `deformation` の等値面が返る。**H⁺ で置いたときと O⁺ で置いたときで差密度が
     違う**（頂点数か `densityMin` / `densityMax` が違う）が、`summary().energy` は同じ。
   - `atomLevels([1], [1])`（H⁺）が返り、中性の H と値が違う。
   - `charges` の長さ違いはエラー、H ひとつに +1 はエラー（電子 0）。
   - 省略したときの結果が今と同じ（既存のテストが全部通る）。
5. `npm run build:wasm` → `web/src/wasm/` が変わる（コミットはユーザーに言われたとき。**CI の
   Linux ビルドとバイトが違うので、push したら `git pull`**）。

## V7-1 で入ったもの

（実測と却下した案は dev-notes「V7-1 の実装メモ」。）

- **組み立て**: `Molecule::from_angstrom(&atoms)?.with_atom_charges(charges: Vec<i32>)
  -> Result<Molecule, GeometryError>`（`Molecule::new` の後でも同じ）。合計を `charge` に入れ、
  多重度を新しい電子数から推し直し、`validate` する。欄は `Molecule.atom_charges: Vec<i32>`
  （`new` / `from_angstrom` は全部 0）。**`charge == atom_charges の和` は `validate` が検査する**
  （`charge` を直接書き換えると `ChargeMismatch`）。
- **`GeometryError` に増えた 3 つ**（既存の `Empty`・`UnsupportedElement { z }`・
  `CoincidentAtoms { a, b }`・`NoElectrons` はそのまま）:
  - `AtomChargeCount { expected, got }` … 長さが原子数と違う →「charges must have one entry per atom」
  - `UnsupportedAtomCharge { atom, z, charge }` … 1 原子に −2 以下、`z` を超える +、**He・Ne・Ar の −**
    （境界の文言は「atom {atom} cannot carry a charge of {charge}」の趣旨）
  - `ChargeMismatch { total, atoms }` … `with_atom_charges` を通せば起きない
  - 電子 0（H ひとつに +1）は今までどおり `NoElectrons` →「… leaves no electrons」
  検査の順は「長さ → 原子ごと → 合計の一致 → 電子数」。**`{:?}` をそのまま流さない**のはチケットどおり。
- **`scan::distance_scan(z: [u8; 2], charges: [i32; 2], from, to, points, kind, on_point)`**
  （`charges` は `z` の直後、同じ並び）。拒まれる電荷の組は**点が 1 つも来ない**スキャンになる
  （エラーにはならない。`dft-wasm` の側で先に `with_atom_charges` を通して文言を出すのがよい）。
  荷電のとき（合計 ≠ 0）だけ、落ちた点を `DriverOptions::default().persistent_scf` で解き直す
  （中性のスキャンは 1 ビットも変わらない）。
- **`guess::atomic_levels(z: u8, charge: i32, kind) -> Result<Vec<f64>, GeometryError>`**
  （戻り値が `Result` になった。今の `dft-wasm` は `0` を渡して `{:?}` で `JsValue` にしている仮の形。
  V7-2 で文言に直す）。`guess::atomic_orbitals(z, charge, kind) -> Result<(System, OrbitalSet), _>`。
- **`orbital::atomic_column(system, atom, orbital, along)` は引数を変えていない**: 電荷は
  `system.molecule.atom_charges[atom]` から読む。**`Calculation` の `System` に原子ごとの電荷が
  入っていれば、軌道の原子の側（`isosurface` の `atom` 付き）は何もしなくてもイオンになる**。
- **電子 0 の原子（H⁺・He²⁺）**: SCF を回さず、密度 0・占有 0、軌道と準位はコア・ハミルトニアンの
  固有値（基底関数の数だけ、Jacobi）。`atomic_levels(1, 1, kind)` は `Ok`（1 段）で、中性の H と
  値が違う。
- **SCF の初期値は原子ごとの電荷を見ない**（`guess::starting_density` ＝ 中性原子の重ね合わせを
  電子数に縮めたもの）。**差密度の基準**（`guess::superposition_of_atomic_densities`）だけが
  置いたとおりのイオン。なので H⁺ で置いても O⁺ で置いても `scf` の答え（エネルギー・密度）は
  **ビット単位で同じ**、差密度だけが違う。engine.test.ts の「エネルギーが同じ」は完全一致で書ける。
- `driver::DriverOptions` から `try_charges` が消えた（`dft-wasm` は触っていなかった）。
  `SpinState.charge` はいつも `molecule.charge`。
- 今の `dft-wasm` の変更は 2 行だけ: `scan` が `[0, 0]`、`atom_levels` が `atomic_levels(element, 0,
  kind)`。**`.wasm` はまだ作っていない**（`web/src/wasm/` は v6 のまま）。
