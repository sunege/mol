# V7-3 イオンの純粋な部分（`SceneAtom.charge`・式・ボタンの可否・文言）

**依存: V7-0**（陰イオンの文言と合計の電荷の上限。「V7-0 で入ったもの」を見る）

**目的**: イオンを扱う**純粋な `.ts` とそのテスト**を先に揃える。原子の型に電荷を足し、
Worker への配列・電荷付きの式（H₃O⁺）・ボタンを押せるか・注意書きと差密度の言葉を決める。
App と viewer は、型が変わって要る分（と下の 2 つの関数の移動）しか触らない（V7-4・V7-5）。

## 前提（今のコード）

- `web/src/scene/viewer.ts` の `export interface SceneAtom { z: number; pos: [number, number,
  number] }`（`grep -n "interface SceneAtom"`）。
- `web/src/molecules/presets.ts` の `toWorkerArrays(atoms): { z: Uint8Array; xyz: Float64Array }`
  （Worker に渡す配列の唯一の出口）。テストは `presets.test.ts`。
- `web/src/App.tsx` の末尾の `function withPositions(atoms, xyz)`（`grep -n "function withPositions"`）
  と、`const atomsOfFlat = useCallback(`（`grep -n "atomsOfFlat"`）が**`{ z, pos }` を組み直して
  いる**ので、このままだと電荷が落ちる（緩和の毎歩・記録・候補から戻した原子）。
- `web/src/records/record.ts` の `hillFormula(z, symbolOf)`（下付きの数字で返す）。
- `web/src/components/density.ts`: 差密度の説明 `WORDS.deformation`（「原子がばらばらだったときと
  比べて、電子が濃くなった場所（青）と薄くなった場所（赤）です。…」）と `explainChannel`。
- ボタンは `components/controls.tsx` の `Segmented`（`label` と `options`、無効の選択肢を持てるかは
  `grep -n "disabled" web/src/components/controls.tsx` で確かめる。無ければ足す）。

## やること

1. **型**: `SceneAtom` に `charge?: -1 | 0 | 1`（省略＝0）。コメントに「電荷は原子に付けるが SCF が
   使うのは合計だけ、原子ごとの値は差密度の基準に効く」。
2. **`toWorkerArrays`** が `charges: Int8Array` も返す（全部 0 でも返す）。テストを足す。
3. **`web/src/molecules/atoms.ts`**（新規、純粋）に App から 2 つを移す:
   `withPositions(atoms, xyz)`（**電荷を保つ**）と `atomsFromFlat(z, xyz, charges?)`。App は
   import に置き換えるだけ（`atomsOfFlat` の `useCallback` の中身が `atomsFromFlat` を呼ぶ）。
   テスト: 位置だけ変わって電荷が残る。
4. **`web/src/components/ion.ts`**（新規、純粋）:
   - `totalCharge(atoms)`、`electronCount(atoms)`（`Σz − Σcharge`）。
   - `chargeChoices(atoms, index)`: 選んだ原子の −1 / 0 / +1 のそれぞれを押せるか。
     **電子が 1 未満になる・合計が上限（V7-0）を超えるものは無効**。今の値は常に押せる。
   - `ION_OPTIONS` と `ION_GROUP_LABEL`（`Segmented` に渡す。文言案: 見出し「イオン」、
     選択肢「− にする」「中性」「+ にする」。短く、3 つが 1 行に収まる長さ）。
   - `chargeSuffix(total)`（`⁺` `⁻` `²⁺` `²⁻`、0 は空）と `formulaWithCharge(formula, total)`
     （`H₃O⁺`）。**式は `hillFormula` のまま**で、電荷は後ろに付けるだけ。
   - `badgeText(charge)`（viewer の印、`+` と `−`（U+2212）。0 は `null`）。
   - `hasAnion(atoms)` と `ANION_CAVEAT`（V7-0 の文言をそのまま）。
5. **差密度の言葉**（`density.ts`）: イオンがあるときの説明を足す。`explainChannel` に
   `hasIons` を渡すか、別の関数で（今の呼び出し側を壊さないほう）。趣旨は「置いた原子・イオンが
   ばらばらだったときと比べて…」で、**H⁺ のように電子を持たないイオンには電子が流れ込んで青く
   見える**ことが読めるように。**数値・基底の名前を出さない。**
6. テスト（`ion.test.ts`・`density.test.ts`・`presets.test.ts`・`atoms.test.ts`）:
   - H ひとつでは「+ にする」が無効、H₂ の 1 つが + なら、もう 1 つの「+ にする」は無効。
   - 上限（V7-0）ちょうどまでは押せて、その先は無効。
   - `formulaWithCharge('H₃O', 1) === 'H₃O⁺'`、`-2` で `²⁻`、0 で式のまま。
   - 文字にどれも数値（小数）や「STO」「LDA」「基底」が入っていない（今の `ladder.test.ts` と
     同じ見方）。

## V7-0 で入ったもの

（実測は dev-notes「v7-0 の実測」の 3〜5。）

- **`ANION_CAVEAT` の文言（そのまま置く）**:
  「陰イオンの余分な電子は、この計算のしかたが苦手とするところです。形は出ますが、余分な電子の
  広がり方は目安として見てください。」
  （板と V7-0 の案の「本当はこの分子に留まりにくい」は採らなかった: OH⁻・F⁻・Cl⁻・CN⁻・NH₂⁻ は
  本当は余分な電子を保つ陰イオンで、最高被占軌道が正に出るのは計算の方法の誤差。「方法が苦手」
  とだけ言えば 1 価にも 2 価にも当てはまる。）
- **合計の電荷の上限は −2〜+2**（`MIN_TOTAL_CHARGE = -2` / `MAX_TOTAL_CHARGE = 2` のような定数。
  コメントに「+3 は最適化で H が飛び散る（CH₄³⁺）、+4 は解けない、−2 は SO₄²⁻ が素直に解ける」）。
  1 原子は −1 / 0 / +1 のまま。`chargeChoices` は「電子が 1 未満」「合計が −2〜+2 の外」に加えて、
  **He・Ne・Ar の「− にする」を無効**にする（最小の基底に余分な電子の入る場所が無く、エンジンが
  黙って電子を 1 つ落とす。貴ガスの陰イオンは実在もしない。V7-1 のエンジンも拒む）。テストに
  「He ひとつでは − が無効、+ は押せる」。
