# V7-7 荷電二原子: スキャンの範囲と相関図の原子の側

**依存: V7-0, V7-4**（荷電の組の上端の倍率は「V7-0 で入ったもの」、`workerClient` の
`charges` は V7-2、ボタンと電荷の流れは V7-4）

**目的**: 原子がちょうど 2 個で電荷があるとき（H₂⁺・HeH⁺・OH⁻ など）、(1) 距離スキャンを
**中性より手前で切り**、(2) 相関図の原子の側を**イオンの準位と名前**（H⁺・O⁻）にし、(3) 原子の線を
押したときの軌道と言葉もイオンのものにする。

## 前提（今のコード）

- `web/src/components/scan.ts`（約 1,300 行。丸ごと読まない）:
  - `SCAN_PRESETS`（H₂・He₂・N₂・O₂・HF、**中性で測った範囲**）と `presetFor(z)`。
  - `rangeAround(distance)`: 0.7〜**1.8** 倍（先頭のコメントに根拠）。
  - `scanPairFor(z, distance): ScanPair`（プリセットがあればそれ、無ければ `rangeAround`）。
  - `buildCorrelation(atoms, symbols, levels, makeup)`（原子の側の列の見出しは `symbols`）。
- `web/src/components/orbital.ts` の `atomOrbitalWords(symbol, name, along)` が
  「`${symbol} の原子の${which}${way}。結合する前の、原子ひとつの部屋です。`」。
- App（`grep -n "scanPairKey" web/src/App.tsx`）: `scanPairKey = "${z0},${z1}"` が
  `atomLevels` の取り直しと相関図の `symbols` の鍵。`.scan(new Uint8Array(pair.z), pair.from,
  pair.to, pair.points, …)`。マーカーを動かすと編集として原子を置き、止まって 400 ms で
  `calculate(placed)`（V5-11。**置き直す原子に電荷を付けたまま**にすること）。
- エンジンのスキャンは状態を最短距離で 1 回選んで固定し、`charges` を受け取る（V7-1・V7-2）。
  `atomLevels(z, charges)` はイオンの自由原子の準位（電子 0 の H⁺ はコア・ハミルトニアンの準位）。

## やること

1. **範囲**: `scanPairFor(z, distance, charges)`。**どちらかが 0 でなければプリセットを使わず**、
   `rangeAround` の上端を V7-0 の倍率（`CHARGED_REACH` などの定数。コメントに V7-0 の根拠を
   1〜2 行）にする。**合計が 0 でも**（Na⁺ と Cl⁻）原子ごとの電荷が 0 でなければ荷電の組として
   扱うかは、V7-0 の表で決まっているほうに従う（NaCl を測っていなければ中性と同じ扱いでよい:
   SCF は合計しか見ないので）。`scan.test.ts` に「荷電の組はプリセットを使わず上端が短い」。
2. **スキャンの注意**: 荷電の組のときだけ、図の下に 1 文（例: 「電気を帯びた 2 つの原子は、離し
   すぎると計算が当てにならなくなるので、ここまでにしています。」）。文言は `scan.ts` が組み立て、
   **数値・基底の名前を出さない**（`scan.test.ts` が絵を歩いて見る今の仕組みに乗せる）。
3. **相関図の原子の側**: `scanPairKey` に電荷を入れる（`"1,+1|2,0"` のような形でも、別の鍵
   でも）。`atomLevels` に電荷を渡す。列の見出しは `formulaWithCharge(symbol, charge)`（H⁺）。
4. **原子の線の言葉**: `atomOrbitalWords` がイオンのとき「H⁺ の 1s。結合する前の、イオン
   ひとつの部屋です。」の趣旨に。**電子の無い部屋**（H⁺ の 1s）であることが読めると良い
   （相関図の原子の側には今も電子の数を描いていない。描き足さない）。`orbital.test.ts` に 1 つ。
5. **ブラウザ**: H₂ を置いて 1 つを + → 分子軌道と「近づけてみる」を開く。スキャンの右端が
   中性の H₂ より短い、原子の列の見出しが「H⁺」と「H」、原子の線を押すと言葉が出る、
   マーカーを動かしても + が残る。HeH⁺ で同じ。

## V7-0 で入ったもの

- **荷電の組の上端は `CHARGED_REACH = 1.4`**（下端は中性と同じ 0.7）。根拠の 1 行: 「H₂⁺ は
  基底の中で厳密な答えとの差が 1.5 倍で井戸の深さの 10% を超え（中性の H₂ は 1.8 倍で 4%）、
  He₂⁺・F₂⁻・Cl₂⁻ は 1.7〜1.8 倍から曲線が寝て下がる（LDA の非局在化誤差）。」（dev-notes「v7-0 の実測」の 2）
- **荷電の組かどうかは合計の電荷で決める**（`charges[0] + charges[1] !== 0`）。Na⁺ と Cl⁻・H⁺ と F⁻ は
  エンジンにとって中性の NaCl・HF と同じ計算なので、中性と同じ 1.8 倍・プリセットもそのまま
  （チケットの「どちらかが 0 でなければ」から変えた）。相関図の原子の側（`atomLevels` と見出し）は
  原子ごとの電荷のまま（Na⁺・Cl⁻）。
- 1.4 倍の内側でも穴が出る組がある: Cl₂⁺・HCl⁺（π に穴 1 つ）は、V7-1 が `scan.rs` に「荷電なら
  落ちた点を粘る設定で解き直す」を入れていれば埋まる（入っていなければ曲線が丸ごと穴）。NaCl⁺ は
  解き直しても穴が残る。どちらも今の「収束しない点は線の穴」の扱いのままでよい。
- ブラウザの確認で時間を見るなら Cl₂⁺: ネイティブで 27 点 24 秒（解き直しあり）。H₂⁺・HeH⁺・OH⁻ は 1 秒前後。

## V7-1 で入ったもの

- **`scan.rs` の「荷電なら落ちた点を粘る設定で解き直す」は入った**（合計の電荷 ≠ 0 のときだけ）。
  0.7〜1.4 倍・27 点で Cl₂⁺・HCl⁺・O₂⁺・He₂⁺ に穴は無い（ネイティブ 27・20・2.3・0.7 秒）。
  ただしそれは **SCF の初期値が中性原子の重ね合わせ（電子数に縮めたもの）だから**で、置いた
  イオン（Cl⁺ + Cl）で始めると Cl₂⁺ は 1.27 倍から先が穴になる（dev-notes「V7-1 の実装メモ」）。
  スキャンの答えは**どちらの原子に印を付けても同じ**（H₂⁺ の [1, 0] と [0, 1] は 1e-10 で一致）。
- 相関図の原子の側はイオンのまま: `atomic_levels(z, charge, kind)`、軌道の絵の
  `atomic_column` は `System` の原子ごとの電荷を読む（配線は V7-2）。H⁺ は電子 0 で、準位は
  コア・ハミルトニアンの 1 段（占有 0）。

## V7-2 で入ったもの

- **`workerClient` の 4 つのメソッドは最後に `charges?: Int8Array`**（原子と同じ並び、省略＝全部中性。
  既定を置くのは `dft-wasm` の `atom_charges` の 1 か所だけ）:
  - `scf(z, xyz, onProgress?, level?, charges?)`
  - `optimize(z, xyz, onStep, onProgress?, budgetMs?, level?, charges?)`（前面は `budgetMs` に
    `undefined` を渡して飛ばす。プールの `#start` は今の `SEARCH_LEVEL` の後ろに足すだけ）
  - `scan(z, from, to, points, onPoint, budgetMs?, charges?)`（`budgetMs` を飛ばすなら `undefined`）
  - `atomLevels(z, charges?)`
  `protocol.ts` の 4 つの要求にも `charges?: Int8Array`。`toWorkerArrays` の `charges` をそのまま渡せる。
- **`ScfOutcome.charge` は指定した合計がそのまま返る**（省略なら 0）。`multiplicity` / `attempts` は
  診断用のまま。
- **エラーの文言**（promise が reject する。`GeometryError` の `{:?}` は流さない）:
  - 長さ違い →「charges must have one entry per atom: expected N, got M」
  - 電子 0（H ひとつに +1、H₂ の両方に +1）→「the total charge leaves no electrons」
  - 1 原子に無理な電荷（−2 以下・`z` を超える +・He/Ne/Ar の −）→
    「atom I (element Z) cannot carry a charge of C」（`I` は `z` の中の位置）
  - UI の決まり（−1/0/+1・合計 −2〜+2・`chargeChoices`）で押せなくしてあれば、どれも起きないはず。
- **`scan` は拒まれる電荷の組を点を解く前に `error` で返す**（エンジンの「点が 1 つも来ない」には
  ならない）。荷電の組は `[1, 0]` と `[0, 1]` で同じ曲線（`engine.test.ts` の H₂⁺ 3 点で完全一致）。
- **`atomLevels(z, charges)` はイオンの準位**: H⁺ は 1 段（中性の H と値が違う）、O⁺ の 1s は O より
  低く O⁻ は高い。軌道の絵の原子の側（`isosurface` の `atom` 付き）は**何も渡さなくても**保持中の
  `Calculation` の電荷でイオンになる（要求に `charges` は無い）。

## V7-3 で入ったもの

- `components/ion.ts`: `formulaWithCharge(symbol, charge)`（`'H' , 1` → `H⁺`、0 は記号のまま）、
  `totalCharge(atoms)`（荷電の組かどうかは `totalCharge(atoms) !== 0`）。
- `toWorkerArrays(atoms)` は `charges: Int8Array` も返す（`scan` / `atomLevels` の最後にそのまま）。
  原子の電荷は `atom.charge ?? 0`（中性は欄が無い）。

## V7-4 で入ったもの

- **電荷は画面の `atoms` にある**（計算タブのイオンのボタン、`chargeSelected`。目印
  `grep -n "The ion row (v7)" web/src/App.tsx`）。`calculate` / 緩和 / 記録の一点計算 / 探索は
  `toWorkerArrays(…).charges` を渡すようになったが、**`scan(` と `atomLevels(` の呼び出しはまだ渡していない**
  （このチケットの仕事）。
- **マーカーの 400 ms の一点計算は `calculate(placed)`** なので、`placed` が電荷を保っていれば電荷付きで解く
  （マーカーが原子を置き直すところで `{ z, pos }` を作り直していないか確かめる）。
- 電荷の変更は `invalidateResult()`（編集と同じ）で、スキャンの結果の扱いもそこに従う。
