# v7 の計画: イオンを置く

**この文書は「なぜこの形なのか」だけを持つ。作業は [docs/v7/README.md](v7/README.md)（板）から。**

v6 までは、置いた原子はいつも中性で、電荷は `driver` が黙って決めていた（中性から解き、
どうしても解けなければ最後の手段で ±1）。v7 では**原子を置いてからボタンでイオンに変え**、
H₂O + H⁺ → H₃O⁺ のような結合を観察できるようにする（2026-09-26 相談・決定）。

エンジンは最初から電荷を持っている（`Molecule.charge`。SCF・勾配・最適化は電荷があっても
そのまま動く）。足すのは「原子ごとの電荷」「それを基準にした差密度」と、それを画面まで通す道。

## 相談のときの実測（2026-09-26、STO-3G / LDA、Medium グリッド）

dev-notes「v7 の相談での実測」に表がある。要点だけ:

- **陽イオンは素直に動く。** H₃O⁺ は 7 歩で O–H 1.03 Å・角度 110° の三角錐、NH₄⁺ は
  正四面体 109.5°、H₃⁺ は正三角形 60°、HeH⁺ は引き離すと He + H⁺ に正しく分かれる。
- **陰イオンは「解けるが、余分な電子が縛られていない」。** OH⁻ の最高被占軌道は +0.60 Ha
  （6-31G\* でも F⁻ は +0.24 Ha）。LDA の自己相互作用と、拡散関数の無い基底が電子を閉じ込めて
  いるだけ。
- **荷電二原子を引き離すと LDA の非局在化誤差が出る。** H₂⁺ は 4 Å で本来ほぼ 0 のところが
  0.09 Ha（約 240 kJ/mol）低く、8 Å で急に 0 へ跳ぶ。
- **イオン結合は中性のままでも見える。** NaCl は STO-3G で Na +0.71 / Cl −0.71（Mulliken）。
  LiF は STO-3G だと 0.02 しか動かず、6-31G\* で 0.48。

## 決まったこと

1. **電荷は原子に付ける。エンジンの SCF が使うのは合計だけ**（`SceneAtom.charge`、−1 / 0 / +1）。
   量子化学では電荷は分子のもので、Na⁺ と Cl⁻ を置いても中性の NaCl と同じ計算になる。それでも
   原子に付けるのは、(a) ユーザーの流れが「H を置く → H⁺ にする」で、(b) 原子ごとの印が本当に
   意味を持つ場所が 3 つあるから: **差密度の基準**・**SAD の初期値**・**相関図の原子の側**。
   計算すると + は散る（H₃O⁺ で H 3 つに +0.41 ずつ、NH₄⁺ はどれがプロトンだったか分からない）。
   それが観察の中心で、差密度で見せる。
2. **電荷は画面に出す（F4 の読み替え）。** 電荷はユーザーが入れたもので、DFT が選ぶパラメータ
   ではなくなる。3D の原子に +/− の印、記録ツリーの見出しに H₃O⁺（状態の行は今も式を
   出していないので足さない）。**多重度・基底・汎関数・試行回数は今までどおり出さない。** 原子ごとの計算上の電荷（Mulliken）も出さない
   （基底でまるで変わる: LiF で 0.02 と 0.48）。
3. **指定された合計の電荷はそのまま解く。`driver` の「最後の手段で ±1」は取り除く。** 画面に
   H₃O⁺ と出ているのに別の電荷の答えを黙って返すことになる。解けなければ今までどおり発散の
   アニメーション（F5）。v6 までのどの記録でも ±1 の段が効いた跡は無い（dev-notes に言及なし）。
4. **差密度（「原子から動いた電子」）の基準は、置いたとおりのイオン。** H⁺ は電子 0 なので基準の
   密度も 0、Na⁺・Cl⁻ はそのイオンの球平均の密度。基準の電子数が分子と一致するので
   「差密度は電子を作らない」（`tr(ΔD S) = 0`）が保たれる。H₂O + H⁺ → H₃O⁺ なら、裸の
   プロトンへ電子が流れ込むのがそのまま見える。**SAD の初期値も同じ関数**（今は「中性原子で
   足して SCF に直させる」。イオンでも電子数が最初から合う）。
   **→ V7-1 で変えた**: 初期値は中性原子の重ね合わせを分子の電子数に縮めたもの（置き方を知らない）。
   イオンで始めると対称な荷電分子（Cl₂⁺・He₂⁺・F₂⁻）で穴が片側に寄って遅く、伸ばした Cl₂⁺ は
   落ち、O₂⁺・Cl₂⁺ は印の位置で別の答えになった（dev-notes「V7-1 の実装メモ」）。基準は計画どおり。
5. **陰イオンは注意書き付きで入れる。** 負の印が 1 つでもあれば出す。文言は V7-0 の実測で決める
   （「余分な電子は本当はこの分子に留まりにくい。この計算では留まって見える」の趣旨）。
6. **荷電二原子の距離スキャンは範囲を切る。** 上端を中性より手前にする（倍率は V7-0 で、
   1 電子の H₂⁺ は HF ＝ 基底の中で厳密なので、それとの差で決める）。プリセットの範囲
   （`SCAN_PRESETS`）は中性で測ったものなので、荷電の組には使わない。
7. **1 原子の電荷は −1 / 0 / +1。電子が 0 になる組み合わせは押せない**（H⁺ ひとつ、H⁺ + H⁺）。
   ボタンは消さずに無効（v5 の規約）。合計の上限は V7-0 で決める（案: −2〜+2）。
8. **記録は原子ごとの電荷を持つ。** ファイルの形が変わるので `LOG_VERSION` を 2 に上げ、
   version 1 は「全部中性」として読む（今までの規約「知らない version は拒否」の例外で、古い
   version を 1 つだけ読む）。比べてよい組の鍵（Hill 式 + 電荷 + `engineModel`）は今のまま
   （`outcome.charge` がいつも指定と一致するようになるだけ）。見出しは H₃O⁺。
9. **探索の候補は電荷を受け継ぐ**（揺らすのは位置だけ）。

## 採らなかった案

- **分子全体に電荷を 1 つ（「この分子は +1」）**: 物理としては正直だが、ユーザーの流れ
  （H を置いて H⁺ にする）と合わず、差密度の基準（どの原子が H⁺ だったか）も決まらない。
- **計算上の原子の電荷を数字で出す**: 基底で符号以外がまるで変わり（LiF）、F4 の精神
  （DFT の数字を教えない）にも反する。「+ が散る」は差密度で見せる。
- **陰イオンを出さない**: ユーザーの選択で、注意書き付きで入れる。
- **荷電二原子のスキャンを出さない**: ユーザーの選択で、範囲を切って出す。
- **拡散関数を足す**: 基底を変えると参照値・記録の `engineModel`・性能の前提が全部動く。
  v7 の範囲外。
