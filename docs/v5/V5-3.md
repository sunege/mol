# V5-3 「計算」「観察」のタブ（＝モード）

**依存: V5-2**

**目的**: パネルの本体を 2 枚のタブに分ける。タブは今の「編集／観測」の切り替えそのもので、
3D のクリックが何をするかとパネルに出ている道具が常に一致する。

## 前提

- **タブ用の状態を持たない。** 選ばれているタブは `mode`（`useState<ViewerMode>`、
  `grep -n "const \[mode" App.tsx`、156 行あたり）そのもの。`'edit'` ＝ 計算、`'observe'` ＝ 観察。
  押したら `chooseMode(next)`（403 行あたり。`restoreModeRef` を捨てて `switchMode`）。
- **自動の切り替えはそのまま効く**: 計算の開始で `observeWhileRunning()` が観察へ、
  発散・エラー・中止で `restoreMode()` が元へ。計算中にユーザーが選んだタブは戻さない
  （`chooseMode` が `restoreModeRef` を捨てるので、今のモードと同じ）。
- タブの帯は V5-2 のヘッダーと本体の間。2 等分で、各タブに小さな副題
  （計算「クリックで原子を置く」／観察「クリックで原子を測る」）。
  `role="tablist"` / `role="tab"` / `aria-selected` / 本体に `role="tabpanel"`。
  ←→ キーで隣へ（任意）。見た目は下線（選ばれたタブに `#3f8cff` の 2px）。
- **振り分け**:
  - **計算**: プリセット（5 列）→ 配置する元素（`PeriodicPicker`）と編集の 3 つ →
    「次の計算」（段の `Segmented`、`levelHint`、`advice`、V5-2 で残した長い説明）→
    いろいろな形を試す（`SearchPanel`、今のまま）。
  - **観察**: 観測（`ObservePanel`）→ 電子密度 → 分子軌道（`OrbitalPanel`）→ 詳細。
  - **記録（`RecordsPanel`）は当面どちらのタブにも出す**: 2 枚のタブパネルの**外**、本体の
    いちばん下に置く。V5-8 で左の欄へ移る。
- **観察タブではプリセットを押せない**ことになるが、それでよい（プリセットは構造を変える操作で、
  観測モードは構造を変える操作を返さない ＝ `gestures.ts` の決まりと揃う）。
- 今の「編集」「観測」の見出し（`<h2>編集</h2>` と ObservePanel の `<h2>観測</h2>`）は
  タブと重なるので、「編集」は「配置する元素」の下の格子に見出し無しで、「観測」は「計測」に。

## 触る場所

- `App.tsx` の JSX: `className="row mode-switch"`（V5-1 で `Segmented` になっている）を
  タブの帯に置き換え、`mode === 'edit' ? (...) : <ObservePanel .../>`（1958〜1996 行あたり）の
  分岐を 2 枚のタブパネルに広げる。プリセット・計算・探索を計算タブへ、電子密度・分子軌道を
  観察タブへ動かす。**中身の部品は動かすだけで書き換えない。**
- **新規** `components/Tabs.tsx`（帯だけ。`mode` と `onChoose` を受ける）。
- `App.css`: `.tabs` / `.tab`。`.mode-switch` の残りがあれば消す。
- `ObservePanel.tsx`: 見出しの文言を「計測」に（1 行）。

## 完了条件

- `npm test`・`npm run lint --workspace web`・`npm run build`。
- Claude のブラウザ（1366×768）で `read_page`:
  - 起動直後は計算タブで、元素表・プリセット・段・探索が見え、電子密度・分子軌道が無い。
  - H₂O で「安定な形にする」を押すと**観察タブに移り**、終わってもそのまま。
  - 観察タブで「計算」を押すと戻り、元素表が出る。計算中に計算タブを押すと、終わっても
    計算タブのまま（戻さない）。
  - 本体の高さ（`scrollHeight`）を両タブで測って dev-notes に残す（V5-11 で前後を比べる）。
- **3D のクリックがタブと一致しているか**（計算タブで置ける・観察タブで測れる）はユーザーに
  Firefox で（V5-11）。

## V5-1 で入ったもの

- `components/controls.tsx`: `Segmented<T>({ label, options: { value, label, title? }[], value,
  onChange, disabled?, small? })`・`Choices<T>({ label, options: { value, label, description? }[],
  value: T | null, onChange, disabled? })`・`ActionGrid({ columns: 2 | 3 | 5, label?, children })`・
  `IconButton({ label, onClick, disabled?, active?, children })`。**`ActionGrid` の中のボタンは
  自分で `className="btn"`**（`primary` / `active` も足す）。
- CSS: `.btn`（`.small` / `.primary` / `.active`）・`.seg`・`.choices`（`.btn.choice` /
  `.choice-label` / `.choice-description`）・`.action-grid.cols-N`・`.icon-btn`。
  **`.row button` の CSS は無い**（`.row` は隙間だけの flex）。`.mode-switch` / `.level-switch` も無い。
- App の目印: モードは `<Segmented label="モード" options={MODE_OPTIONS} value={mode}
  onChange={chooseMode} />`（`grep -n "MODE_OPTIONS"`。定数は import の直後）。タブに替えるなら
  この 1 行と定数を置き換える。段の切り替えは `options={LEVEL_OPTIONS}`。

## V5-2 で入ったもの

- パネルは `<aside className="panel">` の直下が `<StatusHeader …/>`（`.panel-head`）と
  `<div className="panel-body">`（スクロールする本体）の 2 つ。**タブの帯はこの 2 つの間**に
  置く（`.panel` は縦の flex なので、帯は `flex: none` にするだけで固定になる）。
  `grep -n 'className="panel-body"' App.tsx` で引ける。本体の中身は 2 桁ずつ深くなった。
- 本体の先頭は `<p className="phase">`（題の副題）→ モードの `Segmented`。題 `<h1>` は
  ヘッダーにある。
- 計算の見出し（`<h2>計算</h2>`）の下は段の `Segmented`・`levelHint`・`advice`・**長い説明の
  `<p className="hint">` 1 つだけ**（ボタンと「途中までの形」の 1 行はヘッダーへ行った）。
- 本体の最後は `<details className="details">`（`<summary><h2>詳細</h2></summary>` と
  `<dl>` の 4 行: 反復・計算時間・等値面・WebGL）。`describeMesh` は `components/status.ts`。
- ブラウザで確かめるときは、コードを直した後に**ページを再読み込みしてから**測る（HMR で
  `StatusHeader` が差し替わると、主ボタンが効かないことがあった）。「中止」を 1 歩目より前に
  押すと、「すぐ止める」を経ずにその場で止まる（前からの動き）。
