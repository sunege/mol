# V5-7 記録のツリー（純粋な部分とテスト）

**依存: なし**（純粋な `.ts` だけ。ほかのチケットと並行してよい）

**目的**: 記録を「分子 › 段 › 記録」の木に組み、同じ谷の記録を代表 1 件の下に畳む。描くのは
V5-8 で、ここでは**木の形・並び・既定で開く範囲・文言**を決めてテストで固定する。

## 前提

- 材料は `groupRecords(records)`（`web/src/records/log.ts`）が返す `LogGroup[]`。**データの側は
  変えない。** App は現在の分子の群を先頭に並べ替えてから使っている
  （App.tsx の `recordGroups`、`grep -n "const recordGroups" App.tsx`）ので、**木はこの配列を
  受け取り、分子の順は「その分子の群が最初に出てきた順」**にする。
- `LogGroup` の中身（そのまま写す）:
  - `key`（内部。**電荷が入っているので画面に出さない**、F4）、`formula`、
    `level: ModelLevel | null`（知らない `model` の記録は null）、`valleys`（谷の数）、`latest`。
  - `entries`: **落ち着いた記録が先で、エネルギーの低い順**（同じなら古い順）、その後に
    落ち着かなかった記録（新しい順）。
- `LogEntry`: `record`、`settled`、`valley`（谷の番号、低い谷が 0。落ち着かなければ null）、
  `valleySize`、`relative`（kJ/mol）。
- **同じ分子式・同じ段で電荷だけ違う群**は `key` が違う別の群になる。木では**段のノードを群ごとに
  1 つ**作る（名前が同じノードが 2 つ並ぶ。今の見出しも同じなので、そのまま）。

## 木の形

```ts
type RecordTree = FormulaNode[];
interface FormulaNode { kind: 'formula'; id: string; formula: string; count: number; children: LevelNode[] }
interface LevelNode   { kind: 'level'; id: string; group: LogGroup; children: (ValleyNode | RecordLeaf)[] }
interface ValleyNode  { kind: 'valley'; id: string; head: LogEntry; rest: LogEntry[] }  // valleySize >= 2
interface RecordLeaf  { kind: 'record'; id: string; entry: LogEntry }
```

- `id` は開閉を覚えるための鍵で、並べ替えや件数で変わらないこと:
  `f:${formula}`、`g:${group.key}`、`v:${group.key}:${head.record.id}`、`r:${record.id}`。
  （谷の番号は記録が増えると変わるので鍵に使わない。）
- 段のノードの並び: `'shape'` → `'measure'` → `null`。同じ段の群が 2 つあれば出てきた順。
- 段の下: 谷ごとに、**`entries` で最初に出てくる記録を代表（`head`）**、残りを `rest`。
  谷に 1 件しかなければ `ValleyNode` ではなく `RecordLeaf`。落ち着かなかった記録は谷の後ろに
  `RecordLeaf` で並べる。
- **分子のノードは段が 1 つでも作る**（開いたときに段が必ず見える）。

## 既定で開く範囲

`defaultExpanded(tree, { currentFormula, openId }): Set<string>`:
- 画面の分子（`currentFormula`）の分子ノードとその下の段ノードは開く。ほかの分子は閉じる。
- 谷は閉じる。**ただし開いている記録（`openId`）が `rest` にあれば、その谷と祖先を開く**
  （画面に出ている記録が畳まれて見えない、を起こさない）。
- 利用者が開閉したものは V5-8 が覚えて、この既定より優先する（ここでは既定だけ）。

## テストで固定すること

- 同じ谷に 3 件 → `ValleyNode` 1 つ（`head` がエネルギー最低、`rest` 2 件）。
- 谷が 2 つ・1 件ずつ → `RecordLeaf` 2 つ、低いほうが先。
- 落ち着かなかった記録は谷の後ろ。
- 同じ分子で `'shape'` と `'measure'` の群 → 分子ノード 1 つ・段ノード 2 つ、shape が先。
- 電荷だけ違う 2 群 → 段ノード 2 つ（同じ名前）、`id` は別。
- `id` が記録の追加で変わらない（同じ入力に 1 件足して、既存ノードの `id` が同じ）。
- `defaultExpanded`: 画面の分子だけ開く／`openId` が `rest` にあると谷が開く／`currentFormula`
  が null なら何も開かない。
