# V5-9 探索の候補をツリーへ

**依存: V5-8**

**目的**: 「いろいろな形を試す」の候補の一覧を計算タブから出し、記録のツリーの中に入れる。
候補は同じ場所で「順番待ち → 計算中 → 記録」と変わる。計算タブに残るのは始めるボタン 2 つと
1 行の要約。

## 前提

- **終わった候補はもともと記録**: `status` が `'settled'` / `'partial'` の候補は、同じ `id` の
  記録になっている（`candidate.id === record.id`、App の `openCandidate`）。**ツリーでは候補として
  別に描かない**（記録の行がそれ）。
- ツリーに候補として出すもの（`Candidate.status`、`web/src/search/pool.ts`）:
  - `'waiting'` / `'running'` → 回転の印と `statusText(candidate, now)`（「計算中 · 14 回目の移動 ·
    0:42」「順番待ち」）。行の操作は**中止**（`onCancel`）。
  - `'failed'` → 状態は `—`（F5: 数値も失敗の言葉も出さない。今の `statusText` のまま）。押すと
    開く（`openCandidate`。発散のアニメーションになる）。
  - `'cancelled'` / `'unavailable'` → 薄い色で今の `statusText`。操作なし。
  - これらは「終わった候補を消す」（`poolRef.current?.clearFinished()`）で消える。
- **置き場所**: 候補の分子式（`hillFormula(Array.from(candidate.z), symbolOf)`）の分子ノードの下、
  **`SEARCH_LEVEL`（`'shape'`）の段ノードの先頭**。その分子・段の群がまだ無ければ（初めての
  分子を試した直後）**木の側で空の分子ノードと段ノードを作る**。電荷違いで段ノードが 2 つあれば
  最初のほう（候補の電荷はまだ分からない）。
- **純粋な部分は `records/tree.ts` に足す**: `buildTree(groups, pending)`。`pending` は
  `{ id, formula, status, text }[]`（App が `Candidate` から作る。時刻の文字列 `text` は App 側で
  `statusText` を使って作るので、木は時計を知らない）。ノードは
  `{ kind: 'candidate'; id: \`c:${id}\`; ... }`。`tree.test.ts` に: 群の無い分子に候補 →
  分子と段のノードができる／候補は段の先頭／`'settled'` の候補は入れない。
- 既定で開く範囲: **計算中の候補がある分子ノードと段ノードは開く**（`defaultExpanded` に足す）。
- **欄を畳んでいるとき**は、見出しのバッジの横に回転の印を出す（何かが計算中だと分かる）。
- 左の欄の「…」に「すべて中止」（`poolRef.current?.cancelAll()`、計算中が無ければ無効）と
  「終わった候補を消す」（消すものが無ければ無効）を足す。
- `SearchPanel.tsx` に残すもの: 見出し・2 つのボタン（`ActionGrid columns={2}`）・
  `searchSummary(candidates)` の 1 行（空なら何も出さない）・`searchDisabledReason` か短い説明。
  **`SEARCH_HINT` は長いので 1 文に縮める**（「裏側で「形を探す」で計算し、落ち着いた形は左の
  記録に入ります。」程度。`search.test.ts` に文言の検査があれば合わせる）。一覧と
  「すべて中止」「終わった行を消す」は消す。
- 候補の時計は `SearchPanel` の `useNow`（100 ms ごと）が持っていた。**時計は左の欄の中だけで
  回す**（計算中の候補があるあいだだけ。App 全体を 10 回/秒 描き直さない）。`useNow` を
  `components/useNow.ts` に出して両方から使う。

## 触る場所

- `records/tree.ts`（＋テスト）: 候補のノード。
- `components/RecordTree.tsx` / `RecordExplorer.tsx`: 候補の行・「…」の 2 つ・畳んだときの印。
- `components/SearchPanel.tsx`: 一覧を消す。`components/search.ts`: 説明の文言。
- `App.tsx`: `<SearchPanel>` の props を減らし、`<RecordExplorer>` に `candidates` /
  `onCancel` / `onCancelAll` / `onClearFinished` / `onOpenCandidate` を渡す。
- `App.css`: `.candidate*` / `.candidates` / `.search-summary` の塊のうち要らないものを消す。

## 完了条件

- `npm test`・`npm run lint --workspace web`・`npm run build`。
- Claude のブラウザ: H₂O で「ゆらして 3 通り試す」→ 左の H₂O › 形を探す の先頭に候補が 3 行
  （計算中と順番待ち）、終わると記録の行に置き換わる。計算中の 1 行を中止できる。
  欄を畳むと回転の印が見える。計算タブの探索の節が 3 行ほどになっている。

## V5-7 で入ったもの

- 木を組むのは `records/tree.ts` の **`buildRecordTree(groups)`**（チケットの `buildTree` という
  名前ではない）。候補を足すなら **`buildRecordTree(groups, pending = [])` と引数を足す**のが
  いちばん小さい（V5-8 の呼び出しは変えずに済む）。ノードの和は `RecordTreeNode`、段ノードの
  子は `(ValleyNode | RecordLeaf)[]` なので、ここに `CandidateNode` を足す。
- 段ノードの並びは `LEVEL_ORDER`（`'shape'` → `'measure'` → `null`、同じ段は出てきた順）。
  **群の無い分子の分子ノードは今は作らない**（`groups` から作るので）。空の段ノードを作るときは
  `LevelNode.group: LogGroup` が要るので、型を `group: LogGroup | null` にするか、段だけ持つ
  別の形にする（`levelHeading` / `levelMeta` は `LogGroup` を取る）。`FormulaNode.count` は
  記録の件数で、候補は数えていない。
- `defaultExpanded` は「画面の分子とその段」「`openId` が畳まれた谷にあるならその祖先」だけ。
  計算中の候補の祖先はここに足す。テストは `records/tree.test.ts`（記録は `at(kj, extra)` で作る）。

## V5-8 で入ったもの

- **欄は `components/RecordExplorer.tsx`**、App では `.app` の最初の子（`grep -n "<RecordExplorer" App.tsx`）。
  props は `groups` / `openId` / `kept` / `canImport` / `currentFormula` / `onOpen` / `onReplay` /
  `canReplay` / `onRename` / `onDelete` / `onClear` / `onExport(only)` / `onImport` / `notice`。
  木は欄の中で `useMemo(() => buildRecordTree(groups), [groups])`（ここに `pending` を足す）。
- **木の描画は `components/RecordTree.tsx` の 1 コンポーネント**で、中に `formulaRow` / `levelRow` /
  `recordRow(entry, group, depth, valley)` の 3 つの関数。段の子は `levelRow` の中で
  `child.kind === 'valley' ? … : …` で分けている（候補の行はここに 3 つめの枝）。`recordRow` は
  `group`（`settledCount` / `spreadOf`）を使うので、群の無い段ノードを作るならそこを避ける。
  行は `.tree-row`（`paddingLeft = 深さ × 14px`）の中に 26px の枠（`.tree-spacer` か
  くの字の `IconButton`）＋本体。記録の本体は `button.tree-record` で、1 行目 `.tree-name`、
  2 行目 `.tree-sub`（`.tree-relative` / `.tree-count` / 右寄せの `.tree-time`）。候補の
  `statusText` は `.tree-sub` に入れれば揃う。薄い色は `.tree-record.unsettled`。
- **「…」は `components/MoreMenu.tsx`**: `MoreMenu({ label, items: { label, onSelect, disabled? }[],
  note? })`。欄の道具の行の「…」は `RecordExplorer` の `items={[{ label: WORDS.clear, … }]}`
  （「すべて中止」「終わった候補を消す」はここに足す。`note` は `RECORDS_HINT`）。
- **文言は `components/records.ts` の `EXPLORER_WORDS`**（F4 のテスト「the words of the tree」が
  `Object.values` で全部見る）。新しい語はそこに足す。
- **畳んだ帯**は `RecordExplorer` の `if (memory.collapsed)` の枝: `<aside className="explorer collapsed">`
  に開くボタンと `.badge`（件数）だけ。回転の印はバッジの横に足す（見出しの行にも `.badge` がある）。
- **開閉**は `components/explorer.ts`: `expandedIds(tree, choices, { currentFormula, openId })` は
  **分子・段・谷のノードだけ**を歩いて決める（新しい種類のノードに開閉が要るならここに足す）。
  `ancestorsOf(tree, recordId)` も記録と谷しか見ない。計算中の候補の祖先は `defaultExpanded` に
  足せば、押していないノードには効く（ユーザーが閉じた枝は閉じたまま）。
- `IconButton` に `expanded?: boolean`（`aria-expanded`）がある。
